# 美术风格规范（Art Style Guide）

> 项目：**《墨刃 · InkWash》** —— 基于 Unity 的 3D 水墨动作游戏
> 版本：v1.0　｜　制定日期：2026-09-14　｜　状态：**风格已定，主角素材待拍板**
> 关联文档：`Docs/素材来源与授权清单.md`、`Docs/毕设敏捷实施计划.md`

---

## 0. 一句话定位

> **写实比例的中国古风武者，在水墨写意的世界里挥刀。**
> 造型是"东方、古风、飒"，质感是"宣纸、墨迹、飞白"——造型不做卡通化，风格化全部交给渲染承担。

---

## 1. 为什么现在必须定这份规范

用户反馈（原话）：

> 「这个动作跟披风有点穿模，而且这个人物有点太卡通了吧，我们好像还没有确定美术风格，我希望是传统人物，就是东方一点的，比较飒的人物，中国传统古风」

暴露了两个层面的问题，混在一起会互相掩盖：

| 层面 | 具体问题 | 归属 |
|---|---|---|
| **美术方向** | 主角是 KayKit 的 **3 头身 Q 版大头娃娃**，西式游侠装束（绿色兜帽 + 披肩 + 皮护腕），高饱和卡通配色 | 本文档第 2–6 节 |
| **技术实现** | 披风是**蒙皮到脊柱的刚性网格**，手臂摆动时直接穿进去 | 本文档第 8 节 |

**关键判断**：这两件事必须分开处理。换模型不能自动解决穿模（新角色的长袍/披风照样会穿），
而只修穿模也解决不了"太卡通"。所以本文档同时给出**美术判据**与**布料技术方案**。

## 2. 风格定位（Definition）

### 2.1 三条主轴

| 轴 | 取值 | 反面（禁止） |
|---|---|---|
| **文化取向** | 中国传统古风（汉／唐／宋气象） | 西式奇幻、日式和风、仙侠网游堆料风 |
| **写实度** | **写实比例**（7～7.5 头身），半写实材质 | Q 版、大头娃娃、三头身、乐高块面 |
| **气质** | **飒** —— 利落、冷峻、有锋刃感 | 萌、圆润、憨态、玩具感 |

### 2.2 参考坐标（仅取"感觉"，不抄具体作品）

- **形体**：东方武侠影视里的武者体态——肩背挺拔、腰线收束、动作开合大
- **色彩**：国画颜料谱系（墨、朱砂、石青、赭石），忌荧光色
- **质感**：宣纸的粗糙颗粒 + 墨的浓淡层次，边缘有飞白
- **运动**：刀意先于刀身，动作要有"留白"（这一点由 Sprint 4/5 的水墨特效承载）

> ⚠️ **风格化的重心在渲染，不在模型**。用户明确「我主要做的是风格化渲染」——
> 因此选角的硬指标是**比例正常 + 服饰结构正确 + 绑定可用**，
> 而不是"贴图有多精细"（高分辨率 PBR 贴图会被水墨 Shader 覆盖，属于浪费项）。

## 3. 比例与形体规范

| 项 | 规范值 | 说明 |
|---|---|---|
| 头身比（主角） | **7.0 ～ 7.5 头身** | 低于 6 头身即判"卡通化"，不予采用 |
| 总身高（世界单位） | 1.70 m ± 0.05 | 与现有相机（距离 4.3 m）、碰撞胶囊一致 |
| 角色占屏高 | **30% ～ 60%**（现状 43%） | 已有验收项，直接沿用 |
| 剪影要求 | 侧面能一眼分辨"交领 + 束腰 + 下摆"三段结构 | 剪影不清 → 水墨描边糊成一团 |
| 裙摆／披风长度 | 站姿不触地（离地 ≥ 0.05 m） | 贴合现有 FootIK 的贴地窗口 `[-0.02, +0.05]` |

> **现状对照**：KayKit `Rogue_Hooded` 是 3 头身，头部约占全身 1/3 —— 这是用户观感上
> "太卡通"的**唯一主因**，与渲染无关。换掉它必须换成正常头身比。

## 4. 角色设定规范

### 4.1 主角形象基准

**首选形象：古风侠客（汉服体系）**

| 部件 | 规范 | 禁止 |
|---|---|---|
| 上衣 | **交领右衽**，衣襟交叠方向必须正确（右衽是华夏服饰的核心识别特征） | 左衽（丧服／异族误用）、圆领套头 |
| 腰部 | 束腰（腰带／革带），腰线明显收束 | 松垮无腰身 |
| 下装 | 长裤 + 外罩开衩下摆（便于腿部动作不被布料锁死） | 一整片裹裙（必然穿模，见第 8 节） |
| 外披（可选） | 披风／半臂／云肩，**必须带独立布料骨骼** | 刚性披风 |
| 发型 | 发髻／束发 + 发带或发簪 | 散发遮脸（挡水墨描边）、西式短发 |
| 武器 | **单刃直刀（唐刀制式）** 或长剑，佩于腰侧或持于手 | 西式阔剑、日式太刀鞘制 |

### 4.2 形态变体（NPC／敌人，供 M3 之后使用）

同一套规范下可放宽到：道士、僧人、游侠、弓手、官差、农人、老幼。
**共同约束不变**：写实比例、华夏服饰结构、正常色彩。

### 4.3 明确禁止项（含现状违规）

| 禁止 | 现状是否违规 |
|---|---|
| 西式兜帽 / 兜帽斗篷 | ❌ **违规**（KayKit Rogue 的绿色兜帽） |
| 高饱和卡通配色（荧光绿、艳橙） | ❌ **违规**（现状配色） |
| 三头身 / 大头娃娃比例 | ❌ **违规**（现状主体） |
| 裸露的现代／科幻元素 | ✅ 未违规 |
| 日式甲胄与华夏甲胄混搭 | ✅ 未违规（当前无甲胄） |

## 5. 色彩规范

以国画颜料谱系为基准，**角色身上不超过 3 个主色 + 1 个点睛色**。

| 角色 | 色值（参考） | 用途 |
|---|---|---|
| **墨** | `#1C1C1A` ～ `#3A3A36` | 主服色、发色、描边基准 |
| **宣**（米白） | `#E8E2D4` | 内衬、袷衣、下摆 |
| **朱砂** | `#B33A2B` | **点睛色**：腰带／披风里子／发带（全身占比 ≤ 10%，多了就俗） |
| **石青** | `#4A6B7C` | 次要点缀（护腕、滚边） |
| **赭石** | `#8A5A3B` | 皮革／木质配件 |
| **金属** | `#9AA0A6`（低粗糙度） | 兵器、甲片 |

**约束**：
1. 饱和度上限 —— **HSV 的 S 值 ≤ 60%**（现状 KayKit 绿约 S=70~80%，属违规）。
2. 主角不得使用大面积纯色；单一色块面积 ≤ 全身 40%。
3. 点晴色（朱砂）是视觉锚点，用于让玩家在墨色画面里一眼找到自己——**这是玩法需求，不只是审美**。

## 6. 材质与渲染规范

角色材质必须能被现有水墨管线接管。规范如下：

| 项 | 要求 |
|---|---|
| 承载 Shader | 导入后由 `InkWash/*` 系列 Shader 覆盖；源素材保留 URP/Lit 或 Standard 材质作备份 |
| 贴图分辨率 | ≥ 1024×1024；**推荐 2048 或 4K**（角色占屏 43%，近景对贴图敏感） |
| 贴图通道 | 至少含 BaseColor + Normal；Roughness／Metallic 可选（水墨渲染下权重低） |
| 描边 | 依赖法线外扩，因此**模型法线必须干净**（无翻转面、无硬边断裂） |
| UV | 无重叠（重叠会导致墨色错位） |
| 透明度 | 布料边缘尽量走 Alpha Clip 而非 Alpha Blend（避免排序问题） |

> **反过来说**：低模 + 1024 单张贴图的素材（如低模中国风包）在水墨渲染下**并非不可用**，
> 但角色占屏 43% 时棱角会明显外露。面数建议 **≥ 20k triangles**。

## 7. 绑定与动画约束（硬性）

这是本项目最关键的选型门槛 —— 直接决定能不能沿用已经验收通过的移动与连击系统。

| 约束 | 要求 | 为什么 |
|---|---|---|
| **骨架类型** | **必须 Humanoid** | 现有 `Player.controller` 的 9 个状态、`FootIK`、步伐同步（`walkRefSpeed` / `runRefSpeed`）全部建立在 Humanoid 上。Generic 骨架会直接废掉 FootIK |
| **自带动画** | 非必需 | Humanoid 可重定向现有片段。但自带动画可作为动作参考 |
| **布料骨骼** | **强烈建议具备** | 见第 8 节。没有布料骨的长袍角色，穿模只能靠隐藏或重绑解决 |
| **附加骨骼** | 可接受 | 额外的布料／头发／配饰骨骼不影响 Humanoid 映射 |
| **T-Pose / A-Pose** | 记录基准姿态 | 重定向后需校对肩部；现有 `Tools/cs/s3_probe_refspeed_ki.cs` 套路可复用 |

## 8. 披风 / 布料穿模 —— 问题机理与解决方案

### 8.1 机理（为什么现在的披风必然穿）

KayKit `Rogue_Hooded` 的兜帽与披肩是**一整块刚性网格**，蒙皮权重挂在**脊柱与锁骨**上：

```
肩披网格  ──蒙皮权重──>  Spine / Clavicle
手臂摆动  ──>  UpperArm 旋转  ──>  手臂扫过披肩的静态体积  ──>  穿模
```

因为披风**完全不感知手臂**，只要摆臂幅度超过披肩包围盒就必然穿插。
这不是动画问题，**是绑定结构问题**——所以调动画参数永远修不好。

### 8.2 三个方案（按推荐度排序）

| 方案 | 做法 | 优点 | 代价 | 适用 |
|---|---|---|---|---|
| **A. 布料骨骼 + 轻量弹簧求解** ⭐推荐 | 素材自带布料骨链时，写一个 `InkWash/SpringBoneSolver`：逐节做惯性 + 阻尼 + 角度限制，并加一条"手臂排斥"约束 | 可控、可调、性能好、跨角色复用 | 需自研组件（约 150 行） | **新角色自带布料骨**（首选候选即具备） |
| **B. Unity Cloth 组件（PhysX）** | 给披风网格挂 `Cloth`，绑定胶囊碰撞体 | 开箱即用 | 需网格够密；布线与性能开销大；对角色动画（非根运动）支持一般 | 披风面数高的写实素材 |
| **C. 战斗期间隐藏披风**（兜底） | 进入攻击/冲刺状态时把披风 Renderer 淡出 | 一行逻辑，零风险 | 视觉上"披风凭空消失" | 工期紧或 A/B 都不满足时 |

**决策**：优先选**自带布料骨骼**的素材（直接可用方案 A），
若是写实高面数披风则用方案 B，方案 C 仅作兜底并需在论文中说明为降级处理。

### 8.3 验收判据（可测量，写进 PlaytestHarness）

| 指标 | 阈值 | 度量方式 |
|---|---|---|
| 穿模帧占比 | **< 5%** | 逐帧取"披风网格顶点"与"上臂/前臂骨骼胶囊"的最短距离，< 0 判穿模 |
| 最坏穿透深度 | **< 0.02 m** | 同上，取最小值 |
| 布料骨骼跟随延迟 | 甩动后 ≤ 0.25 s 回稳 | 记录骨骼角速度衰减 |
| 帧率影响 | 1080p 仍 **≥ 55 fps** | 沿用现有 DoD |

> ⚠️ 该度量与现有姿态体检（`S2_pose_latest.txt`）同属"几何体检"，需并入
> `Tools/cs/` 下的自动化流程，报告落 `Tools/reports/`。

**三、顺手挖出并修掉的真缺陷**（两个在 `FootIK.cs`、一个在 `SwordVfx.cs`，**都是换模型才暴露**的）

1. **竖直偏移的单位错配 —— 走错了空间**
   `stateOffsets` 是**世界米**（标定脚本量的就是世界量），却写进了 `anim.bodyPosition`——那是
   **Animator 局部空间**。模型带整体缩放（`Visual.localScale = 2.213`）时，世界效果被放大
   **4.90 倍 = 2.213²**（实测：写 0.0257 抬了 0.1260）。
   同一通道上的 `BodyLift` 反馈增益也被放大 4.9 倍 → 必然过冲。现象：Walk 名义抬 0.057 结果飘
   +0.134；Run 名义压 0.229 结果沉 −0.274。
   **修法**：输出通道改为**模型容器的 `localPosition.y`**（`bodyOffsetTarget`，自动解析为 Animator 的
   直系子节点 = `Visual`）。它的父节点无缩放 → 局部 Y **就是世界米，1:1**，从此与模型缩放彻底解耦。
   *KayKit 时代缩放为 1，两个空间数值恰好相等，所以这个错一直没暴露。*

2. **静态偏移与帧内抬升重复补偿 —— `need` 没扣掉 `BodyBase`**
   `BodyLift` 的 `need` 原本按**原始姿态**算；但静态偏移 `BodyBase` 已经抬过一次了，于是同一个
   穿地量被补偿两遍。KayKit 时代 9 段偏移全为负、原始最低点恒为正 → `need` 恒 ≤ 0 →
   `BodyLift` 恒为 0 → 这条路根本没被走到。Feng 有负的原始最低点，立刻显形。
   **修法**：`need = (地面 + clearance) − 最低点 − BodyBase`，`BodyLift` 只补**静态偏移之后的残差**。

### 二、挂点：**"剑身对齐手指方向"是错的**（本轮最大的认知修正）

上一版把剑身对齐到**手骨 +Y（手指伸出的方向）**，理由是"骨骼沿自身 +Y 延伸"。
实测数据说明这个理由**引错了类比**：

| 量 | 值（Idle 期，世界） | 说明 |
|---|---|---|
| `fingerDir`（手骨 +Y） | (0.430, −0.869, 0.247) | 手指伸出的方向，几乎朝下 |
| `spreadDir`（食指根 → 小指根） | (0.457, −0.031, −0.889) | **拳头的铰链轴 = 拳头隧道轴** |
| `palmNormal` = `fingerDir × spreadDir` | (0.779, 0.495, 0.384) | 掌面法向 |

**握剑时剑柄穿过的是"拳头隧道"，它的轴 = `spreadDir`，不是 `fingerDir`。**
用 `fingerDir` 会把剑摆成"从指缝里长出来"；用 `spreadDir` 才是"握在手里"。

方向的正负号由**掌根 → 虎口**的对角线定：剑刃从**拇指与食指之间**穿出。
实测该对角线 `heel→web` 与 `−spreadDir` 夹角仅 **27.4°**（与 `+spreadDir` 是 152.6°），
所以取 **剑身方向 = −spreadDir**。副产品：这个方向与角色 `forward` 夹角只有 **27.3°**
⇒ 待机时剑自然指向**身前**，不用额外调姿势。

**挂点公式**（`P` = Align 局部位移，`R` = Align 局部旋转，`s` = Align 缩放，`v` = 模型空间点）：

```
p_root = P + R·(s·v)                        # 模型点 → 根（= 手骨）空间
要求：① R·(0,−1,0) = d（d = 根空间里的剑身方向；模型尖端在模型 −Y）
      ② 模型上的握持点 v0 = (0, Gm, 0) 落到拳心 f
⇒  P = f + s·Gm·d            （Gm = 剑柄中点 0.4050，f = 拳心在根空间的坐标）
```

> **⚠ 上一版就是漏了 ②**：写成 `P = s·Gm·d`，等于假设"根原点（= 腕关节）就是握持点"。
> 实测腕→拳心 **0.141 m**，于是剑柄中点被摆在了**腕**上，拳头正好卡在**护手**上
> （护手在腕前 0.1475 m，与拳心 0.141 m 吻合 —— 数据早就摆在那儿，是我没去核对）。

**最终序列化值**（全部在**手骨局部空间**，与姿势无关）：

| 字段 | 值 |
|---|---|
| `Align.localPosition` | `(−0.005492450, 0.062623090, 0.204533600)` |
| `Align.localRotation` | `(−0.499112900, −0.500882100, 0.499116400, 0.500885400)` |
| `Align.localScale` | `(0.49, 0.49, 0.49)`（不变） |
| `SwordVfx.bladeLocalOffset` | `(−0.005491800, 0.062286160, 0.299759600)` |
| 拳心 `f` | `(−0.005494, 0.063325, 0.006085)`（根空间单位，×2.213 = 0.141 m） |

`roll` 的选法：让**剑的刃面法向（模型 Z）= 掌法向**（`flatN` 方案）。
理由：挥砍时刃线落在斩击平面内、刃面朝掌面外 —— 这是锤握的自然姿态。
（两候选 `flatN` / `flatN_neg` 都渲染过：`sword_solve/solve_flatN*.png`。）

### 三、握拳补丁 `WeaponHandPose`

**问题**：本项目的动画包**全是徒手动作**（Quaternius UAL1/UAL2 + Kevin Iglesias 只有
`Idle01` / `Walk01_Forward` / `Run01_Forward` 三个片段），手一直是张开的"放松手"。
挂剑后看着像把剑**搁**在手心 —— 这是**换真模型才暴露**的问题，占位剑阶段看不出来。

**做法**：`LateUpdate`（`DefaultExecutionOrder(20000)`）里把持剑手的指骨绕 `spreadDir` 卷起来。

三条硬约束（都踩过）：
1. **必须在 `LateUpdate`**：`Update` 里改会被 Animator 当帧写回，白改。
2. **局部轴要"卷之前"一次性取好，再统一卷**：等价于真实指关节的铰链。
   边卷边取轴 → 各节各绕一个世界轴 → 指头散开。实测卷指后近节转 **68.7°**（请求 70°），
   中指指尖到腕从 0.141 m 收到 **0.111 m**。
3. **`CC_Base` 骨架把脚趾也叫 `Index/Mid/Ring/PinkyToe1`** —— 按名字抓指骨必须
   `if (name.Contains("Toe")) continue;`。本轮就是漏了这句，"拳心"被 4 根脚趾骨
   拖到 y = 0.93（离腕 **0.69 m**），差点据此把挂点算到膝盖上。

**自检**：`Tools/cs/w_shot_play2.cs` 会实测锚点
**到剑轴垂距 = 0.0000 m、在剑身 66.2% 处（= 刀刃段的 55%）**，判据 `[通过] 锚点落在剑身上`。

### 五、材质的一处反直觉实测

场景**没有任何反射探针**（`defaultReflectionResolution = 128`，走默认天空盒）。

最终取 `_Metallic 0.30 / _Smoothness 0.38`。
另外 `texture_pbr_20250901_roughness.png` 是**数据贴图**，导入必须
`sRGBTexture = false`（已修，是个潜在陷阱）。

### 六、本轮踩坑清单（下次接武器直接照做）

1. **别用节点 `TransformDirection(up)` 判剑身方向** —— 本模型尖端在网格空间 −Y，
   节点轴天然反向，会误报"夹角 180°，朝向错了"（假警报，害我多查一轮）。

2. **节点轴/注释都会撒谎**，先量再说（这条已在 S2.1 总结过，本轮又验证一次）。
3. **换挂点方向 = 换一套数值**：`Align` 的 pos + rot、`bladeLocalOffset`
   三处必须一起改，只改一处等于没改。
4. **Play 态写资产会被 WriteGuard 拦**：先 `stop` 再改，再 `play` 验。
5. **新加的 `.cs` 不在 `Assembly-CSharp`**：`ImportAsset(ForceUpdate)` →

## 9.5 待机动作「持剑而立」—— 2026-09-15 修正

### 一、现象与根因

用户反馈：待机姿态「奇葩」—— 手臂自然下垂，剑**水平横戳**向体侧。拆开看是**两个独立问题**叠加。

**（1）控制器没跟着角色换（表层）**

`Player.controller` 最后一次改动是 `5278fd0`（换 KayKit 那一步）。之后角色换成 `Char_Feng`，
控制器却没动 —— 实测 **9 个状态全是 KayKit 的 Q 版片段**（`Idle_A` / `Walking_A` / `Running_A` /
`Melee_1H_*`）。`Idle_A` 是给三头身小人做的「立正」待机，套在写实古风角色上自然别扭。

**（2）徒手动画 + 刚性握持 = 剑必然横着（本质，这条更重要）**

剑身方向**固死**在手骨上（手骨局部 `+Z`，物理上正确 —— 拳头握剑的几何关系是常量）。
而「手臂自然下垂」时**前臂是竖直的**，剑身与前臂近似**垂直** ⇒ 剑只能**水平**伸出。

绕前臂轴做腕部旋前 / 旋后**救不了**。实测扫描（扭转 0° / 45° / 90° / 135°）：

| 扭转角 | 0° | 45° | 90° | 135° |
|---|---|---|---|---|
| 剑与「竖直向下」夹角 | 109.9° | 99.9° | 83.0° | 68.3° |

即剑只是在**绕前臂画圈**，收敛在水平附近，**永远指不到正下方**。

> **推论（选持剑待机片段的判据）**：任何「手臂垂下」的待机片段都**不适合持剑角色**。
> 持剑待机必须是**屈肘**姿态 —— 肘一屈、前臂转成水平，与它垂直的剑身就自然立起来了。

### 二、处置

`Idle` 状态片段由 `KayKit/Rig_Medium_General.fbx::Idle_A` 换成
**`Assets/Char_Feng/Animation/Idle.anim`**（同作者、同骨架、**零下载**）。
它是**真正的持剑待机**：左手收袖、右手屈肘竖剑于肩前。
实测剑与「竖直向下」夹角 **144.9°**（即立起来、指向斜前上方），换之前是 **91.6°**（水平）。

按规范，换片段**必须**重测 `FootIK.stateOffsets`（它绑「片段 × 骨架」）。
实测 Feng 的 Idle 让网格最低点沉到地面下 **0.0277 m** ⇒ `Idle` 偏移由 `-0.0003` 改为 **`+0.0307`**
（其余 8 段保持不变）。

**验收**：S1 31/0 · S2 51/0 · 姿态 4/0 · 音频 6/0，Console 无红字。
刀光锚点复核：换算到武器网格局部空间后为 `(0.0000, -0.1943, 0.0000)`，
**离剑轴 0.0000 m**（Idle / Walk / Atk1 / Atk3 四态一致）。

### 三、新增可量化判据

| 指标 | 怎么量 | 判据 |
|---|---|---|
| 剑是否立起来 | `weapon.TransformDirection(Vector3.down)` 与 `Vector3.down` 的夹角 | 越接近 0°（朝下）或 180°（朝上）越好；**90° = 水平横戳，不合格** |
| 刀光锚点是否贴合 | 锚点换算到**武器网格局部空间**后的 `sqrt(x² + z²)` | 必须 = 0.0000 m |
| 待机脚部贴地 | 网格最低点（`BakeMesh` 逐顶点，按归一化时间扫） | 落在 `[-0.02, +0.05]` m |

> ⚠ **「剑身 X%」有两个分母，别混**：从**剑首端**算是 **66.2%**，从**护手到剑尖**（真正的「剑身」）算是 **53.4%**。
> 本项目的刀光锚点是同一个点，两处都写过（§9.4 四 与验收表）。

### 四、遗留：控制器整体仍是 Q 版时代

`Walk` / `Run` / `Dash` / 三段攻击**仍是 KayKit 片段**（Feng 自带 10 段里只有 `Idle` / `Walk` / `Roll` /
`Death` 等，**没有 Run、没有挥剑**）。所以目前存在**风格断裂**：待机是写实古风，一动起来又切回 Q 版节奏。
建议按「移动优先」重排：`Walk` → `Feng/Walk`，`Run` → `KevinIglesias/Run01_Forward`，攻击段暂留待换。

## 9.6 平时站立 vs 战斗待机 —— 双姿态（2026-09-15）

### 一、需求

用户反馈：不只是拿剑的待机，**平时站着也应该是自然双手下垂**的动作。

### 二、根因：与 §9.5 是同一个

「垂手站立」与「手里握着剑」**在几何上冲突**：剑身方向固死在手骨上，手臂自然下垂时前臂竖直，
与它近似垂直的剑身只能水平横伸（实测与「竖直向下」夹角 88.4°）。

所以**换片段救不了** —— 把 Idle 换成垂手片段，剑照样横在身侧。
证据在同一张对比图里：`stand_cand/A_UAL1_IdleLoop_front.png` 与 `E_反例_垂手但剑在手_front.png`
**姿态完全相同、只差剑显不显示**，前者干净、后者剑横在身前。

> **结论：非战斗时必须把剑收起来，而不是只换动画。**

### 三、方案：战斗 / 非战斗 双姿态

新增 `Assets/_Project/Scripts/Player/CombatStance.cs`。

| | 非战斗（默认） | 战斗 |
|---|---|---|
| Idle 片段 | `UAL1/Rig\|Idle_Loop`（自然双手下垂） | `Char_Feng/Idle.anim`（持剑待机） |
| 武器挂点 | `BackSocket`（背部） | `CC_Base_R_Hand`（右手） |
| 握拳补丁 | 关闭 | 开启 |

- **进入战斗**：`SwingStarted`（攻击）或 `DashStarted`（冲刺）
- **退出战斗**：连续 `combatExitDelay`（默认 6 s）既没攻击也没冲刺，且已回到 `Locomotion`

**实现选择**：用 `AnimatorOverrideController` 只覆盖 **Idle 这一个片段**的映射，
**不动 `Player.controller` 资产**。理由是新增状态要牵动所有进出转移的条件（回归面太大），
而这里要变的只有「Idle 播哪段」。

### 四、背部挂点：沿用 socket 约定 + 轴向自动探明

`BackSocket` 建在 `CC_Base_Spine02` 下，局部位姿：

```
pos = (-0.041672, 0.196906, -0.055625)   euler = (62.475, 92.689, 180.269)   scale = 1
```

剑尖方向取 `down + 0.55·right`（右肩柄 → 左腰尖），刃厚法向取 `back`（宽面贴背）。
效果：剑柄露在**右肩上方**（右手可过肩拔剑），剑尖到左小腿，**正面完全看不到剑**。

三条踩过的坑：

1. **轴向必须实测，不能凭记忆。** `Align` 节点上**还留着 FBX 的原生旋转**
   （实测 `euler = (0, 270, 89.8)`，不是之前以为的 `(180, 0, 0)`），于是
   「武器根局部 +Y 指向剑尖」这个假设**是错的** —— 实测剑尖方向 = 根局部 **+Z**。
   正确做法：把「网格节点的 −Y（剑尖）/ +Z（刃厚）」用 `InverseTransformDirection`
   换算到武器根局部空间，再 `FromToRotation` 对齐（实测对齐残差 **0.05°**）。
2. **位置锚点必须说清是「根原点」还是「网格中心」**——两者相差 **0.47 m**。
   直接摆根原点，整把剑明显偏低：剑柄落到腰侧而不是肩上方，右手没法过肩拔剑。
3. **socket 原点 = 挂载点**（同 §9.4 的武器约定）。因此运行时搬运武器只要
   `SetParent(socket, false)` + 局部归零即可，组件**不需要存任何「挂点偏移 / 缩放」字段**。

### 五、验收

- **S1 31/0 · S2 51/0 · 姿态 4/0 · 音频 6/0**，Console error 0。
  姿态验收「最飘 Idle 0.005 m」—— 换成 UAL1 垂手后脚部贴地依然达标，`FootIK` 不用重标。

## 9.7 攻击时左手五指摊开 —— 左右手的铰链轴是**镜像**的（2026-09-15）

### 一、现象

用户拿战斗截图反馈：「为什么他的这个手还是会打开，太奇怪了，**在攻击的时候，待机动作没问题**」。

把截图放大（裁切 + 5 倍插值）后看清了两件事：持剑的**右手是握住的**（正常），
**左（空）手五指完全摊开**。

### 二、先量后判：定义「握拳度」

写 `Tools/cs/q_fist2.cs`，对 `Idle` / `Atk1` / `Atk2` / `Atk3` 逐状态打印四指的关节夹角与
「中指指尖到腕」距离，并定义**尺度无关**的握拳度：

> **握拳度 = 中指指尖到腕的距离 ÷ 食指根到小指根的距离**
> 五指摊开 ≈ 2.2 ～ 2.4；握成拳 ≈ 1.2 ～ 1.4。
> 分母选「指根展开宽度」是因为它在卷指过程中几乎不变（转轴就在指根上），
> 于是这个比值天然**不随模型缩放漂移**。

| 状态 | 右手（持剑） | 左手（空手） |
|---|---|---|
| Idle（Feng 持剑待机） | 1.55 | 1.50 |
| Atk1 / Atk2 / Atk3 | 1.34 | **2.33 ← 摊开** |

两个结论：

1. **右手一直是握着的**（补丁生效）—— 用户看到的确实是左手。
2. **「待机没问题」不是巧合**：Feng 自带的 `Idle` 本来就把左手做成半握（1.50），
   而 KayKit 的攻击片段把左手摊到 2.33。而 `WeaponHandPose` 的 `leftHand` 默认 **false**，
   `CombatStance` 只负责整开关（`handPose.enabled = combat`）—— **根本没人管左手**。

### 三、真因：`spreadDir` 是**镜像轴**

顺手把 `leftHand` 打开，数值**几乎不动**（近节 36.6° → 48.1°、指尖到腕 0.193 → 0.189 m），
而且「满力 70/85/55」与「六成力 48/58/38」给出**完全相同**的结果 —— 说明不是力度问题，
是**方向反了**。

写 `Tools/cs/q_fist3.cs` 关掉组件、自己按同样的公式对左右手各试三个候选轴：

| 试法 | 右手 中指指尖到腕 | 左手 中指指尖到腕 |
|---|---|---|
| 基线（不卷） | 0.128 m | 0.124 m |
| **+70° 绕 spreadDir** | **0.108 m ← 屈 ✓** | **0.214 m ← 伸 ✗** |
| −70° 绕 spreadDir | 0.125 m | **0.114 m ← 屈 ✓** |
| +70° 绕 palmN（掌法向） | 0.119 m | 0.174 m |

> **`spreadDir = 小指根 − 食指根` 在左右手上是镜像的，人手本身也是镜像的。**
> 沿同一个正角度旋转，一侧是「屈」、另一侧是「伸」（等于反向掰直）。
> 这就是「左手照抄右手的角度只会把手掰得更开」的原因。
>
> 顺带否掉了一个更直觉的猜测：**不是轴不正交**。自检 `|cos(骨向, spreadDir)|` 左右手都是
> 0.001 ～ 0.117，横竖都接近垂直 —— 轴是对的，**符号是错的**。

### 四、处置：符号必须**实测**，不能写死

在 `WeaponHandPose.Resolve()` 里给每只手做一次**当场试转**（`CalibrateSign`）：
沿 `+spreadDir` 把食指链三节各转 40°，**若中指指尖离腕更远就取反**。

- 实测 `RightCurlSign = +1`、`LeftCurlSign = −1`
- 写死「左手取负」也能过，但**换骨架 / 换手性就又错**；试一次的成本只有几行 `localRotation` 赋值。
  与 §9.4 / §9.6 同一套原则：**能用一次实测换掉的假设就别留着**（轴向、挂点、符号……）
- 给左手单独一组更松的角度（`leftFingerCurl = 58/70/45`）：空手握拳不必像握剑那么死
- 轴仍然「在卷之前一次性取好」（卷了父骨之后子骨的局部轴会变，见 §9.4）

**修复前后**

| | 修复前 | 修复后 |
|---|---|---|
| 左手握拳度（攻击中） | 2.33 | **1.29** |
| 左手 中指指尖到腕 | 0.193 m | **0.107 m** |
| `RightFistRatio` / `LeftFistRatio`（运行时探针） | 无 | 已暴露 |

### 五、新增验收项

`PlaytestHarness` 在战斗采样里记录**握拳度峰值**，S2 增一行（51 → 52 项）：

```
[通过] 攻击全程两手都握着（不是五指摊开）   握拳度峰值 右 1.547 / 左 1.356（五指摊开≈2.2，握成拳≈1.2）
```

阈值取 1.7 —— 距「握拳 1.4」与「摊开 2.2」两侧各留 ≈ 0.5 的余量。
**只在「补丁这一帧确实跑过」时采信**（`pose.enabled && CurledBoneCount > 0`）：
探针都是 `LateUpdate` 末尾写的，刚进战斗那一帧读到的是**上一帧的陈旧值**。

> ⚠ **探针的陈旧帧陷阱**：组件被 `disabled` 时 `LateUpdate` 不再跑，
> 但 `Armed` / `CurledBoneCount` / 握拳度**全都停在最后一次的值上**。
> 外部代码读这些探针必须**同时看 `enabled`**，否则会把「上一次战斗」的残留当成当前状态。
> （同类问题在 §9.6 的 `FootIK` 上也出现过。）

### 六、遗留

`Walk` / `Run` / 三段攻击**仍是 KayKit 的 Q 版片段**（Feng 自带 10 段里没有 Run、没有挥剑），
所以**风格断裂**依旧存在：待机是写实古风，一动起来切回 Q 版节奏。
攻击段的**握持**问题已由本补丁兜住，但动作本身仍是 Q 版。

## 9.8 三段攻击换成 UAL2 剑术库 —— 并炸出 FootIK 的「探地正反馈」（2026-09-15）

### 一、现象

### 四、换片段顺带炸出的 FootIK 真缺陷：**探地正反馈**

换完片段 S2_pose 立刻报 `Atk2Rec -0.878 m`。诊断（`Tools/cs/q_footdiag.cs`）显示这些帧
**`HasGroundInfo = false`** —— 链条如下：

> `ProbeGround` 的射线起点 = `网格最低点 + probeUp(0.5)`。
> UAL2 的收招段把角色压到地下 **0.5~0.9 m**（它比 KayKit 的直立挥砍激进得多），
> 起点随之落到**地面之下**，而射线是**向下**发的 ⇒ 永远打不到地面
> ⇒ `HasGroundInfo = false` ⇒ `BodyLift` 归零不修 ⇒ **沉得更深，更探不到**。**正反馈**。

修法三条（前两条是通用缺陷，换任何"大幅下蹲"的片段都会撞上）：

1. **探测起点改用 `max(网格最低点, 角色根 Y) + probeUp`** —— 角色根由 `CharacterController`
   保持在地面附近，是可靠锚点；网格最低点会被动画压得很低，不能单独作锚。
2. **`maxLift` 0.8 → 1.3** —— 最深需要一次性抬 0.89 m，卡上限会永远差一截。
3. `stateOffsets` 的 `Atk1 / Atk1Rec / Atk2 / Atk2Rec / Atk3` 重标。
   **取「最浅穿地量」作基准**（而不是最深）：这样每帧 `need = 地面 − 最低点 − 基准 ≥ 0` 恒成立，
   帧内抬升全程有效；取最深值会让浅的帧 `need < 0` 而浮空（抬升只能向上、压不下去）。

## 9.9 移动片段去 Q 版化 + 攻击提速（2026-09-15）

### 一、现象

### 二、先量再判：两个判据

**① 「张臂」看 >55° 的**时间占比**，不看峰值。**

| 候选 | 左臂外展峰值 | **>55° 占比** |
|---|---|---|
| KayKit `Walking_A`（原现状） | 78.8° | **100%** |
| **Feng 自带 `Walk`** | **21.2°** | **0%** |
| Kevin Iglesias `Walk01_Forward` | 32.7° | 0% |
| KayKit `Running_A`（原现状） | 84.8° | 80% |
| **KI `Run01_Forward`** | 94.9° | **46%** |

100% 意味着「整段都摆着那个姿势」，而不是摆臂瞬间抬一下 —— 与 §9.8 同一条判据。

**② 参考速度必须重标，而且连旧片段的值也一并作废。**

`walkRefSpeed = 0.69` 是 KayKit 模型时代标的。换成 Feng 骨架后腿变长，重定向把步伐一起放大
——**同一个 `Walking_A` 在 Feng 上实测是 1.32 m/s**。旧值让 `MotionSpeed = 1.0 / 0.69 = 1.45`，
比正确值高 1.9 倍 ⇒ 腿倒腾得比真人快 50%（步频 2.72 步/秒，真人走路 1.5~2.0）。

> **参考速度绑的是「片段 × 骨架」**，与 §9.1.2 的 `FootIK.stateOffsets` 同一条规矩。

**③ 标定改用**脚踝骨骼**，不能用网格最低点。**

真人比例模型走路时脚掌会「脚跟→脚尖」滚动，**网格最低点在着地相内部平移了约一个脚掌长
（0.25 m）**，被当成「脚相对根的后移」⇒ 速度虚高近一倍（v1 把 Feng Walk 量成 2.25 m/s，实际 0.91；
单步 1.50 m 对 1.78 m 身高而言是跨步跳，常识校验一眼就能看出不对）。
改用 `HumanBodyBones.LeftFoot / RightFoot` 逐脚判定着地相（脚踝进入「该脚最低点 + 4 cm」）后：

| 片段 | 时长 | 原生地面速度 | 步频 | 单步位移 |
|---|---|---|---|---|
| KayKit `Walking_A` | 1.067 s | 1.32 m/s | 1.88 | 0.70 m |
| **Feng `Walk`** | 1.333 s | **0.91 m/s** | 1.50 | 0.61 m |
| KI `Walk01_Forward` | 0.800 s | 1.80 m/s | 2.50 | 0.72 m |
| KayKit `Running_A` | 0.800 s | 5.48 m/s | 2.50 | 2.19 m ← 不合理 |
| **KI `Run01_Forward`** | 0.600 s | **4.12 m/s** | 3.33 | 1.24 m ✓ |

标定脚本 `Tools/cs/q_refspeed2.cs`；候选对比与连拍 `Tools/cs/q_movecand.cs`。

### 四、`FootIK.stateOffsets` 重标：两种口径要对号入座

换 `Walk` / `Run` 片段必须重测（§9.1.2）。重标脚本 `Tools/cs/q_footik2.cs` 同时打印**最深 / 最浅**：

| 状态 | 无IK最深 | 无IK最浅 | 新值 | 口径 |
|---|---|---|---|---|
| `Walk` | −0.1053 | +0.0604 | **−0.0554** | 取**最浅**：脚全程该踩地 ⇒ BodyLift 逐帧把其余帧压回地面 |
| `Run` | −0.1685 | +0.3632 | **+0.1735** | 取**最深**：有腾空相 ⇒ 支撑相贴地、腾空相自然离地 |

判据（读 `FootIK.ApplyBodyOffset` + `s2_acc_pose`）：`need = (ground + clearance) − low.y − BodyBase`，
`BodyLift = Clamp(need, 0, maxLift)`，**只上抬**。收敛后「贴地后最低点」= `max(min(rel) + BodyBase, clearance)`：

- **基准 ≤ `clearance − min(rel)` 就不穿地**（验收 6 只看这一条 ⇒ 基准取到那个上界也能过）
- 但基准越大，越会**整段固定抬高**（浮空）；越小，BodyLift 逐帧抬得越多（且受 `liftSmooth` 滞后限制）

⇒ 按「**哪些帧应该贴地**」选口径，不能一律取最深、也不能一律取最浅。

### 五、验收判据的一处修正：窗口要裁到事件边界

换完片段后 S2 报 **`握拳度峰值 右 1.701`**（阈值 1.7，上一版 1.34）。全场景扫描
（`Tools/cs/q_fist5.cs`，逐状态记录峰值）定位：

| 状态 | 右手 | 左手 |
|---|---|---|
| Idle / Walk / Dash / Atk1 / Atk1Rec / Atk2 / Atk2Rec / Atk3 | 1.547 | 1.29 ~ 1.58 |
| **Run** | **1.701** | 1.611 |

**峰值出现在 Run，不在攻击。** 判据名是「**攻击全程**两手都握着」，而采样是**整个战斗 stage**
逐帧跑的 —— 战斗中的跑步帧（`Run01_Forward` 的基础手姿势是半张开的）把峰值抬了上去。
修法：`PlaytestHarness.CaptureCombatSample` 的采信条件加 `IsAttackState(anim)`。

> 这与「事件型指标的**窗口必须裁到事件边界**」是同一条规矩（否则相邻事件互相污染、数值虚高），
> 是**第二次**踩同一个坑（第一次见 §9.7 的「陈旧帧陷阱」）。

顺带确认两件事：**跑步时手半握不是缺陷** —— `WeaponHandPose` 是「在动画基础姿势上叠加固定角度」，
跑步摆臂本来就该半握；**攻击帧右手恒为 1.547**（卷到关节极限，形态固定）符合预期。
