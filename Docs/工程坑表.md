## 一、为什么要有这张表

这个工程反复被同一类错误咬：**"静默失效"**——不报错、不崩溃、控制台干净，
只是某个东西再也不工作。下面每一条都是踩过的坑，凡标 ★★ 的是代价最高的。

## 二、静默失效类（最贵）

| # | 规则 | 代价 |
|---|---|---|
| 1 | **别靠字符串名匹配找资产**（改名后**静默失效零报错**）⇒ 显式字段优先，失配要吵 | 改名即断链，无人发现 |
| 2 | **★ 改 C# 默认值不生效**：C# 与 prefab 序列化值都要改，改完 grep 复核（**`Edit` 会静默丢改动**） | 改了等于没改 |
| 3 | **★ 改资产（`.mat`/`.shader`/`.asset`）后必须 `refresh`**；**HLSL 错误不进 Console** ⇒ 靠 `ShaderUtil.GetShaderMessages` | 以为生效了 |
| 4 | **★ 新增 shader uniform ⇒ 4 个 `UnityPerMaterial` CBUFFER 逐字段同序同类型**（不一致**不报错不崩**，只让 SRP Batcher 静默失效）；`HasProperty` 只证明 shader 声明了它 ⇒ 关键属性显式写进 `.mat` | 性能静默劣化 |
| 5 | **★ 被禁用的 MonoBehaviour 不执行 `Update()`** ⇒ 场景里误存的 `enabled=False`（做演示场时为不刷怪关的）让整条链**全静默停摆**：入口照常调用、状态机照常迁移、控制台干净，只有计时器永不动 ⇒ **入口方法要自愈**（`if (!enabled) enabled = true;`） | 波次永不启动 |
| 6 | **★ 特效资产必须存在才算数**：`Shader.Find` 失败时材质工厂**静默退回 `URP/Unlit`**（不吃顶点色） | 视觉全错但不报错 |
| 7 | **★ 克隆跨 prefab 骨架子树会让 `m_Bones` 全悬空**（纯空白零报错）⇒ `PrefabUtility.InstantiatePrefab` 整体挂 | 模型空白 |
| 8 | **★ `NavMeshAgent` 建不起来会静默自由落体** ⇒ `Update()` 锁地兜底 | 敌人穿地 |
| 9 | **★ 判定"素材到位"别看文件数**：Unity 会自己补 `.meta`（`ThirdParty` 2517→2765 里 **+248 全是 `.meta`，实际资产一个没多**）⇒ 唯一可信判据是 `check_clone_deps.py` 的**悬空引用数** | 误判"已到位" |
| 10 | **★ 豁免是"给某类动作开的例外"** ⇒ 换片段必须复查（断言里的 `continue` 会**同时关掉「修复」与「验收」两条路**）；**「自动」≠「正确」** ⇒ 人眼选片段、数据选参数 | 验收名存实亡 |
| 11 | ~~★ "编辑模式读到 mesh=null" 先查导入新鲜度~~ **⚠ 本条归因已于 09-17 被证伪**：`Ctrl+R` 强制重导入（`ArtifactDB` mtime 已晚于资产）后，**四种读法（`LoadAssetAtPath` / 单数 / `LoadPrefabContents` / `InstantiatePrefab`）仍全部得到 `SMR=1 / mesh=null`** ⇒ 不是导入陈旧，是**引用本身悬空**（见第 12 条）。**仍然成立的部分**：拼装 prefab 的占位**连 `m_Mesh` 字段都没有**，单看本文件「读出来空」是必然的 | 白查一轮 |
| 12 | **★★ 引用会被静默写坏**：`{fileID, guid, type}` 只要 **fileID 在目标文件里不存在** ⇒ 解析为 `null` 且**不报错**。09-17 实锤：`d31bc8e` 把 `Z_Dragon.prefab` 的 `m_Mesh` 写成 `-3325053396650211315`，全工程 **284 个 Model / 569 个 Mesh 零命中** ⇒ Play 实测 **0 像素**，而 Console 干净、`sharedMesh` 只是在别处读到 null。**判据（两条都要）**：① `AssetDatabase.TryGetGUIDAndLocalFileIdentifier` 逐条验、**必须命中**（同 fbx 的材质 id 被精确匹配上 ⇒ 尺子可信）② 实渲量非背景像素。**「扫到 0 条命中」必须当成失败**（字节序写错也会恒 0 命中） | 整只龙渲染不出来，无人察觉 |
| 13 | **★★ 反向陷阱：只改 prefab、不改 C# 默认值，同样会静默失效**（第 2 条的镜像，09-18 实锤）。第十四轮把 `restLift / restMotionScale / restSpeedScale` 从 `0.35 / 0.06 / 0.12` 改成 `4.5 / 0.5 / 0.45`，**只写了 prefab** ⇒ 演示场（走 prefab）验收通过、源码里却仍躺着「静默段把身体完全拉直 + 贴地 0.35 m」的旧行为；组件一旦被 `Reset()`、prefab 被重建或回退，旧行为当场复活。**判据 = 逐字段比对「脚本默认值 vs prefab 序列化值」** ⇒ 工具 `Tools/check_prefab_overrides.py`（无参数直接跑内置的墨龙组合，也可传 `<prefab> <script.cs>`）。**对齐方向一律「以 prefab 为准改源码」** —— prefab 才是被验收过的那份，而且改源码默认值**零行为变化**（prefab 本来就覆盖它），纯防御。⚠ `int/float/bool` 要按数值比（prefab 里 bool 序列化成 `0/1`，直接字符串比会把 `true vs 1` 全报成差异） | 源码默认值悄悄腐烂成「没人记得的旧行为」 |

> **配套读法**：编辑模式读 prefab 要用能**强制展开**的方式 —— `PrefabUtility.LoadPrefabContents`
> 或 `InstantiatePrefab`，并同时打印 `PrefabUtility.GetCorrespondingObjectFromSource()` 的解析结果
> （探针 `Tools/cs/molong_smr_probe.cs` 四种读法对照）。
> **⚠ 但"四种读法全空"不是结论，只是排除法**：09-17 之后必须**再加一步**——把那条引用拿去
> `TryGetGUIDAndLocalFileIdentifier` 对账（`Tools/cs/dg_prefab_forensic.cs` / `dg_mesh_hunt.cs`）。
> **读法再多也验不出坏引用；验引用才是判据。**
> **签名/回退看最小 diff**：改 prefab 引用一律 `git diff` 只看那几行 + `git checkout <旧commit> -- <file>` 回退单个文件，
> **不要整目录回退**（会把同批的实质改动一起洗掉）。

## 三、验收与度量纪律

1. **★★ 验收断言不许写死期望值** ⇒ 从**被测配置/实测**推导（`PlaytestHarness.ConfiguredSpawnCount()`）。
   写死的数**不会报错**，只会让验收在配置变更那天**静默失效** —— 波数 `==3`、刷怪 `>=8`、
   S4「敌人非水墨」四条曾同时失效而无人看见。
2. **保险丝同理**：帧数上限随帧率与配置漂移 ⇒ 真正的上限用**墙钟**，并强制报出退出原因
   （通关 / 阵亡 / 时间到 / 保险丝），"未通关"不再同时对应三种处置。
3. **度量窗口必须裁到事件边界**；只差一项未通过 → **先怀疑度量本身**。
4. **★★ 量之前先怀疑尺子**：掩码/统计函数必须**自检并报命中数**（"0 像素"会被误读成
   "完美通过"；命中数荒诞 = 阈值被天空盒撑爆）｜相机机位要**算**不要试｜
   对照帧必须**同 tick 背靠背 `Camera.Render()`**｜量"期间高度变化"用期间极差、
   量"间隔"以事件开始时刻为基准。
5. **一次性「运行时实测」不可靠** ⇒ 每帧实测 + 判不出沿用上一帧 + 迟滞。
6. **★ 别靠字符串/节点轴做几何约定** —— 注释会撒谎、节点轴会撒谎 ⇒ 判方向用包围盒逐顶点真值。
7. **★★ 「有网格」≠「看得见」**：`sharedMesh != null` 只证明引用有效，**真判据是实渲一次量非背景像素**。
   09-17 反例：`Z_Enemy_MoShan`（14/14 网格）与 `Z_Enemy_MoGuai`（10/10 网格）**实渲 0 像素**
   （宽取景仍 0），而旧验收 `Tools/cs/chk_enemy_vis.cs` 判它们 ✅ ⇒ **该判据有盲区**：
   **真因已于同日定案并修复，见 10.（骨骼引用全 null）**。判据应改成「**实渲量像素 + 逐元素查 `smr.bones` 非 null 数**」（已落实到 `Tools/cs/chk_enemy_vis.cs`）。
   **度量自身还有三个陷阱**（同一天连踩三次）：
   - **★ `Camera.enabled = false` 时 `Camera.Render()` 只清屏、不画模型** ⇒ 给出 **0.00% 假阴性**。
     *发现方式*：4 张 PNG 与修复前**字节完全相同（72101）**，而成图正常的 `dg_look` 是 716 KB
     ⇒ **出图量级要顺手看一眼**，别只信算出来的百分比。
   - **★ 一刀切禁用 MonoBehaviour 会让 `InkMaterialSwap` 不跑** ⇒ 运行时要靠它贴的材质**全 null**
     ⇒ 假"不可见"。只关会捣乱的那一个（这里是 `NavMeshAgent`）。
   - **★ 取景 union 所有 `Renderer.bounds` 会被离群包围盒拖偏**（`MoGuai` 的 `mesh.bounds` 是
     **1269×1964×566 m**）⇒ 只并入 **max 边长 0.01~20 m** 的包围盒（离群过滤），并同时报出被剔除的个数。
   - **收口手段**：仍有疑问时 `Time.timeScale = 0f` 冻结 + **固定大范围**（正交 6 m / 40 m）各拍一张，
     才能分辨「没画」与「跑到别处」。工具 `Tools/cs/dg_enemy_shots.cs`（v2 已修全）、`dg_enemy_diag.cs`、`dg_enemy_wide.cs`。
8. **★★ 哨兵背景色：① 抖动幅度必须 < 阈值 ② 绝不与「缺材质色」撞色**（09-17 三踩）：
   - **① 8-bit RT 有 dithering**。实测同一张纯色背景抖出的值：**绿 `(0,255,0)` → 最大 `(44,240,44)`（差 62）**，
     阈值 24 下 ⇒ **恒定的 25.63% 假"非背景"**；**纯蓝 `(0,0,255)` → 差 ≤21**、
     **纯红 `(255,0,0)` → 差 ≤21** ⇒ 干净。
     出图上是**几乎看不见的同心条纹**（Bayer 图案），肉眼极易误判成"模型轮廓"。
     **识别特征：换取景尺度、换模型，读数一模一样 ⇒ 那是噪声，不是被测物。**
   - **② ★ 哨兵色绝不能用洋红 `(255,0,255)`** —— **那正是 Unity「材质丢失」时渲染的颜色**。
     结果：**看图的任何人在视觉上都无法区分「我铺的画布」与「真的缺材质」**。
     实测代价：用户看到一片洋红直接问"为什么会材质丢失"，我上一轮也据此误判过
     「MoShan 渲染成品红 = 缺材质」（被 `dg_enemy_far` 证伪）。
     **⇒ 哨兵色一律用纯蓝 `(0,0,255)`**（需要第二底色时用纯红）。
     连带纪律：**给临时物选色时，先问"这个颜色在 Unity 里是不是有既定的含义"**。
   - **③ 阈值不能设在噪声带内**：想用 `luma < 100` 判"深色像素"，而洋红抖动值 `(240,0,240)` 的 luma = **98.4 < 100**、
     基准 `(255,0,255)` = **104.55 > 100** ⇒ 同一个纯色背景被劈成两半（四个不同 prefab 全都恒报 67.87%）。
   - **★ 规矩**：跑像素判据前，**先对空场景拍一张，确认读数是 0.00%**（零点自检），
     并把"换尺度/换模型不变"当作噪声的指纹。危险的是**它不报错，只给一个稳定的假数字**。
   - **★ 白拿的强判据：换底色，读数不变的那部分才是被测物。** MoGu 的 `RGB(12,9,8)` 共 37671 px，
     蓝底与红底下**一个不差**；MoShan 在两种底下量化色都只有 2 种且**全是底色自身的抖动值**。
9. **★ 直方图比百分比有用**：百分比只说"多/少"，**直方图说"是什么"**。
   （量化色数 3 vs 29 一眼分开；「像素数完全相同」的某一项就是真渲染出的东西。）
10. **★★★ 「网格在、材质在，就是画不出来」的头号元凶：`SkinnedMeshRenderer` 的骨骼引用全 null**（09-17 定案）：
   - **判据**：**逐元素**数 `smr.bones` 里的非 null 个数。**只看 `bones.Length` 会漏** ——
     长度正常（26/80/97）而元素**全为 null**，正是本项目三个 Ziyuan 敌人的状态。
   - **普查规律**（8 个敌人/龙 prefab）：非 null 骨骼 > 0 的**全部正常渲染**；
     = 0 的两个（`Z_Enemy_MoShan` 0/14、`Z_Enemy_MoGuai` 0/10）**一个像素都不画**。
   - **三档对照一次定性**（`Tools/cs/dg_smr_rebuild.cs`）：新 SMR + 同 mesh **不给骨骼** = 0%（Unity 正常行为）；
     新 SMR + **同一份** mesh + **有效骨骼引用** = **画出来了** ⇒ 根因确凿。
   - **同时证明网格 / 材质无罪**：同一个 `sharedMesh` + 同一材质挂普通 `MeshRenderer` 直画 ⇒ 完整显示。
   - ✅ **同日已修复。真因不是 FBX 骨架坏了，是 prefab 把引用写死成了 `{fileID: 0}`** ——
     实测上游 FBX **全部健康**（`mountain_orge` 26/26、`low-poly_orc` 97/97、
     `cursed_undead_soldier_rig` 80/80），而 prefab 里每个 SMR 的 `m_Bones` 是
     **1574 条写死的 `{fileID: 0}`**（MoShan 364 / MoGuai 970 / MoGu 240）+ `m_RootBone: {fileID: 0}`。
     **修法 = 按源 FBX 里同名 SMR 的 bones 顺序，把 prefab 内同名 Transform 接回去**
     （`Tools/cs/bf_fix.cs`：`LoadPrefabContents` → 填 `smr.bones` / `rootBone` → `SaveAsPrefabAsset`）。
     **顺序必须照抄源 FBX**（必须与 `mesh.bindposes` 一致，不能自己排序）。
     修后：MoShan **6.269%**、MoGuai **9.301%**、MoGu 只留 SMR **4.884%**（原均 0.000%）。
   - ⚠️ **所以遇到「骨骼全 null」先别急着换渲染器**：本项目的骨架树在 prefab 内**是完整的本地副本**，
     缺的只是引用 ⇒ **接线比换渲染器更省事**，且不影响任何按 `SkinnedMeshRenderer` 查对象的代码
     （`PlaytestHarness.cs` 三处写死的查找因此不用改）。
     判断方法：源 FBX 里同名 SMR 的 `bones` 是否有效、prefab 内骨架节点名是否与它一一对应。
   - **若确实要换渲染器**（静态敌人、骨架也确实没有）：改用 `MeshFilter` + `MeshRenderer`。
     换之前先查有没有代码**只按 `SkinnedMeshRenderer` 找对象**（换材质组件 / 验收脚本），否则会静默漏掉。
   - ✅ **原以为的"反例"已解释清楚，判据成立**：`Z_Enemy_MoGu` 骨骼全 null 却看得见，
     是因为它身上除了 3 个 SMR **还有 4 个普通 `MeshRenderer`**（静态网格 `Object_28/34/43/90`）。
     在演示场里拆开量（`Tools/cs/dg_sc_verify.cs`，见 11.）：**只留 SMR = 0.000%（两帧逐字节相同）**，
     **只留 MeshRenderer = 1.930%** —— 它的可见部分 100% 来自那 4 块静态网格。
     ⇒ 「非 null 骨骼 = 0 ⇒ 不画」**没有反例**；同时说明这类模型**本来就该走 `MeshRenderer`**。
   - ⚠️ **dump 结构化对象必须 `NextVisible(true)` 展开数组**：用 `Next(false)` 时
     `m_Bones` / `m_Materials` / `m_BlendShapeWeights` **全是盲区**，会得出「字段零差异」的**假结论**。
   把"非背景像素"逐色统计（量化 4 bit/通道）后，噪声与模型一眼可分 ——
   本例噪声是 18 种"淡色"、模型是**同一个颜色在两种背景下像素数完全相同**
   （`MoGu` 的 `(12,9,8)` = 37671 px，绿底品红底都一样）⇒ 那才是真渲染出来的东西。
   工具 `Tools/cs/dg_pixel_hist.cs`。完整诊断链 → `Docs/敌人0像素-诊断记录.md`。

11. **★★★ 可见性度量必须在「真实测试场景 + 正常相机」里做**（09-17 用户指出，一次踩满五个坑）：
    - **★ 用测试场景，不要在正式关卡里自搭台**。本项目 = `Assets/_Project/Scenes/Showcase.unity`
      + `ActionShowcase`：地面用真资产 `M_Whitebox_Ground.mat`、三盏灯、`Showcase_Camera`，
      并且**召唤走 `PlayForCapture(index)`、枚举走 `ItemCount`/`ItemLabel`**（都是为截图留的公开入口）。
      在 `Main.unity` 里另起相机/灯光、把 prefab 丢到 `y=300` 空中量的结果**不代表游戏里看到的**。
      自搭板子还会顺手丢东西：演示场注释写明"手拼材质在宣纸后处理下会过曝成一片白"。
    - **★ 判据用「同 tick 背靠背差分帧」，连哨兵色一起省掉**：同一相机、中间**不 yield**，
      渲染器【开】渲一次、【关】再渲一次，逐像素求差 ⇒ 差集就是它画出来的像素。
      与背景色/曝光/后处理/哨兵色全无关，还能顺手用 **md5 是否相同**给出无可辩驳的结论。
      两帧都把被测对象的 `shadowCastingMode` 置 `Off` ⇒ 差集是**纯几何像素**、不含投影。
    - **★ 「0 像素」必须自带两条保险**，否则它也可能只是"没拍着"：
      ① **在视锥内**（`GeometryUtility.TestPlanesAABB`）② **同一批里有一个读得出来的阳性对照**
      （本项目就用墨龙 2.063%）。两次读数打架（MoGu 一次 0.331%、一次 0.000%）⇒ **先查取景**。
    - **★ 对准相机的方向别算反**：`pos = look + dir * dist` 里 `dir` 要**由对象指向相机**。
      我把符号弄反 ⇒ 相机落到 `y = −1.25`（地面以下）⇒ 被 60 m 地板整个挡住 ⇒ **连墨龙都读 0.000%**。
      顺手纪律：把**相机位置与"是否在地面之上"一起打进报告**。
    - **★ 清场时别把自己删掉**：探针自己就叫 `dg_xxx`，用 `StartsWith("dg_")` 扫根对象清场会**自杀**
      （表现是"脚本启动了但什么都没产出"）。清场循环里先 `if (root == gameObject) continue;`。
    - **★ 一刀切禁 `MonoBehaviour` 这条坑又踩了一次**（见 7.）：探针里图省事关了全部 MonoBehaviour，

18. **★★★ 骨骼链「包络指数」决定端点动不动 —— 指数 ≥2 时端点恒不转**（09-18 踩）：
   症状：用户看画面说「现在这个头和后面的爪子，还有尾巴都没有动呢」。
   查了两轮才定性 —— **不是幅度不够，是几何上不可能动**。
   曲线 `lat(u) = amp · sin(πu)^n · sin(2πWu + φ)`，端点的**切向**由 `lat'(0)` 决定：
   - `n ≥ 2` ⇒ `lat'(0) = n·sin^{n-1}(0)·cos(0)·π = 0`，**与相位无关、恒为 0**
     ⇒ 端点切向 = 纯轴向 ⇒ 第 0 节（尾）与末节（头）**永远不转**。调 `amp`、调频率都救不回来。
   - `n = 1` ⇒ `lat'(0) = π·amp·sin(φ) ≠ 0`（除 φ = kπ 的瞬时）
     ⇒ 端点切向随相位来回摆 ⇒ 「段方向角极差」≠ 0。
   **★ 指数 1 与 ≥2 是"端点动不动"的分水岭**，不是包络形状的调参问题。
   验收口径：`段方向角极差`（该节段方向相对容器 fwd 的最大−最小），阈值 5°；
   旧的「弦垂距」判据对这件事**完全不敏感**（弦垂距大只说明"身体是弯的"）。

19. **★★★ 包络两端可以非零，但 `lat(0)` 必须为 0，否则身体退化成单侧 C 形**（09-18 踩）：
   链的第 0 节**位置**被父级 `_rootJoint` 钉死 ⇒ 链的实际横向形状 = 曲线横向值 − **曲线在起点的值**。
   把包络改成"线性渐变（两端增益≈1）"后 `lat(0) ≠ 0`，这个差值在某些相位下**全体同号**：
   实测段 B 帧 00 的 lat（i=6..15）全为负，截图里就是"一条弧"而不是 S 形。
   **⇒ 两条约束（端点方向非零 + 端点位置归零）同时满足的简单解只有
   `env = sin(πu)^1 × 线性增益`。**
   ★ 顺带更正一个想当然的前提：「曲线起点必须落在链根上」**不是**硬约束 ——
   驱动只用曲线的**方向**（相邻点之差），曲线整体平移不改变任何一节的朝向。
   真正不能动的是**链根的位置**，不是曲线起点。这个错误前提让我上一轮选了归零包络。

26. **★★★ 长链骨架上「挂在链节点上的附件」必须单独对齐**（09-18 定，第十八轮）：
   龙/蛇这类模型，头（一大簇骨 + 鬃须角颌）、尾（28 骨 / 3.24 m）都是**挂在脊柱某一节上的分支**。
   拉直脊柱**不改变它们的相对姿态** ⇒ 它们会一直保持模型原生的俯仰/滚转。
   - **头**：对 `_spine[Count-2]` 之下、不属于任何 `_limbRoots` 分支的骨做 **PCA 第一主轴**
     （= 颅骨/吻部，排除鬃须角颌）。实测 50 枚骨、长轴 (−0.584,−0.503,−0.637)、俯仰 **30.2°**、
     展布 0.864 m / 垂直半径 0.359 m（扁平度 2.41 ⇒ 长轴可信）⇒ **抬头 30°** 让长轴水平。
     ★ 必须**量**，不能眼估；★ 也**别**用"头扇叶子骨的均值方向"当指标（那是颅顶/鬃根，
     量到 52.4°，照着做会把头**往下压** 52°，与要的正好相反）。
   - **尾**：把整条链的段方向**压回水平面**（目标方向只用 `back` 与 `right` ⇒ 恒水平），
     横向叠一个 `amp·u` 包络的行波（**尾根为 0** 才与身体无缝相接，否则根部分相对身体突移一个常量）。
   - ★ 只转 `_spine[Count-2]` **一节**就够（`Count-1` 是无几何的链尾骨）
     ⇒ 头**整块绕颈根转**、脖子一动不动，不会像"事后左乘"那样把 sin 形状揉歪。
   - ★ 用**整旋转**（`extra * q`）而不是只转目标方向：只转方向的话 `FromToRotation` 是最小旋转、
     绕骨轴的 roll 不受控 ⇒ 头会"转过去了但扭着"。
   - ★ 两条驱动路径（`ApplySpineOffsetsRaw` / `ApplySerpentineSpine`）必须**行为一致**，
     否则相位一进一出，头会"啪"地弹一下。

27b. **★★★ 「尾巴没跟上身体的 sin」= 两条独立缺陷，不是"幅度没调够"**（09-18 定，第十九轮）：
   用户原话「现在这个尾巴还是没有跟上 sin 的」。真因拆开是两件事，各自单独都会露馅：
   - **① 传播方向相反**：身体是 `lat = amp·sin(πu)·sin(2πWu + ph)`（`u` 身体→尾），
     旧尾巴写成 `lat = amp·u·sin(−2πWu + ph)` —— 相位前**负号**让波峰往**相反方向**走。
     ⇒ 两条波在接点处**对着撞**。（「相位前的符号 = 传播方向」这条在第 6 条已写过，
     但当时只用在脊骨上；**分支链上是独立的第二处代码，别再忘**。）
   - **② 接点切向不连续**：旧尾巴根节横向速度 `d(lat)/du|₀ = amp·sin(ph)`（`u` 的线性包络 ⇒ 根部斜率≠0），
     而身体在 `u=0` 的斜率是 `π·amp·sin(ph)` ⇒ 两侧**差 π 倍**。
     实测 接点折角 **20.67° 均值 / 31.82° 最大**，而身体自己相邻节的折角只有 **10.16°**。
   - **★ 结构性正解：让尾巴成为身体那条曲线往 `u<0` 的「延长」，而不是第二条波。**
     把身体曲线的**同一组参数**（`amp / W / gain / 总骨长`）交给尾巴，取 `u_curve = u_tail · (−L_tail/bodyTotal)`：
     ```
     u < 0 ⇒ env = sin(πu) < 0      // ★ 这个负号是接点切向连续的关键，不能取绝对值
     lat = amp · env · sin(2π·W·u + ph)      // 与身体同一个 W、同一个 ph
     ```
     ⇒ 波长 / 相位 / 传播方向 / 接点切向**全部由构造保证连续**，不靠调参。
     实测：接点折角 **20.67° → 6.11°**（均值），尾尖横摆 p2p **0.686 → 1.982 m**，
     身体中段两种模式都是 **1.750 m**（尺子自检 ✅ 完全没动）。
   - **★ 接点必须用"两侧切线"判，不能用"两侧位置"判** —— 位置不管怎么接都连续（都在 `_spine[0]`）。
   - ★ 另设开关 `tailFollowBodyWave`（默认 true）+ `tailFollowGain`（默认 0.9）；
     折返保险丝：`amp·gain·(2π·W)/Σ骨长 < 1`（本龙 `Σ骨长 8.266 m`）。
     攻击相位（`ApplySpineOffsetsRaw` 那条路径）身体不是正弦曲线 ⇒ 保持 `follow=false` 走旧行为，
     两条路径**不能同时开 follow**。

28. **★★★ 判「接点有没有断」之前，先量这把尺子的「本底」**（09-18 踩，第十九轮）：
   - 我一开始把判据写成「接点折角 ≈ 0°」，结果修完量到 **6.11°** ⇒ 差点判"没修好"。
     补跑 `drg_kinkbase.cs` 一量才知道：**身体自己内部相邻节的折角均值就有 10.16°**。
   - 真因是**弦驱动链的固有偏差**：骨方向 = 相邻两个采样点的**弦**，不是真切线 ⇒
     `偏差 ≈ ½·lat''·Δu/T`，**只与段长一阶相关**（身体首段 0.237 m / 尾巴首段 0.246 m ⇒ 量级相同）。
     ⇒ 接点折角**永远不可能真的 0°**。正确的判据是**比值**：
     `接点折角均值 / 身体内部折角均值`，**≈1 = 一样平滑**。
     实测 修后 **0.60**（比身体自己还平），修前 **2.04**（差一倍）。
   - **⇒ 口诀：要判"某处有没有断裂/跳变"，必须先在同一个度量上量一个「已知良好」的内部参照。**
     凡是"应当恒等于 0"的判据，先问一句"这把尺子在本底最小时读数是多少"。
   - 同理适用于"接点 / 关节 / 缝合处"的一切平滑性判据。

## 六、AI / Boss 行为

- **★★ 基类 `CanSeePlayer()` 是"地面怪"心智** ⇒ Boss 必须覆写 `TickIdle`/`TickChase`
  （龙朝 +Z、`sightAngleDeg 200°` 只覆盖 ±100°，玩家站背后**永不被发现**）。

- **★★ 材质参数面板必须「按源材质分族」** —— `InkStylePanel.Broadcast()` 遍历 ALL entries
  会把主角墨阶盖到每个敌人头上。
- **★★★ 墨龙「僵硬」= 四条独立成因，不是「参数没调好」**（第十四轮 09-17 定案）：
  ① **波长恰好一个整波 ⇒ 弯曲自我抵消**：24 节 × `hoverPhaseStepDeg 15°` = **360°**，

     占身长 8.2 m 的 **5.7%**（真蛇 10~15%）；
  ③ **行波相位前的符号 = 传播方向**（`ph = phase + i·step`）：`− i·step` 让波峰**尾→头**，
     真龙是**头先转向**；i 小 = 尾/根侧（`drgon_03`→`drgon_00`）；
  ④ **垂直分量形同虚设**：`hoverPitchAmplitudeDeg 1.5` / `hoverAmplitudeDeg 16` = **9%**
     ⇒ 近乎纯水平摆动 =「会摆的扁片」。修后 **16/35 = 0.48**（目标 0.35~0.60）。
  - 附加：旧「蛇行」加在 **radial**（离玩家远近）分量上 ⇒ 轨迹是**花瓣形**而非 S 形；
    且被 `*0.12` 压成 ±0.31 的方向偏置，又被同括号的 err 修正吃掉 ⇒ 实测接近一个圆。
    **摆航向**（`AngleAxis(deg, up) * baseDir`）走出来的才是 S 形。
  - **★ 判据：弦垂距**（链相对「尾→头弦」的最大垂距），并**拆水平/垂直分量再比**。
    实测 均值 0.86 m（旧最小 0.00 = 笔直）、垂直/水平 **0.48**（旧 0.04）。
    **两个错的口径**：每节 `localRotation` 绕角（行波下相邻节几乎同相）、
    Y跨度÷XZ跨度（恒 ~0.09，因为 XZ 由 8 m 身长主导）。
  - **★ 别让「省电模式」和核心表演打架**：`enablePerformanceCycle` 的静止段旧值
    （`restMotionScale 0.06`）会把身体**完全拉直**且贴地 0.35 m，与「时时刻刻保持 S 形 +
    高空巡游」直接冲突。修法是**降度 + 放缓 + 仍蛇形**（`0.5/4.5/0.45`），不是关掉特性。
- **★★★ 驱动骨骼链只能「绝对写入」，绝不能「事后左乘叠加」**（09-18 实测，代价是整条龙蜷成一个圈）：
  - **正确**：`_spine[i].rotation = root · AngleAxis(yaw,up) · AngleAxis(pitch,right) · _baseRel[i]`
    —— 绝对式，每帧从基准重算 ⇒ **无累积**；
  - **错误**：`_spine[i].rotation = AngleAxis(θ_i, worldAxis) * _spine[i].rotation`
    —— "读当前世界旋转再乘"。**这些 Transform 是父子链**，而 `rotation` setter 写的是**世界旋转**：
      父骨一转，所有子骨的世界旋转跟着变，于是逐个乘下去就**累积**了。
      实测 24 节 × 平均增益 0.9 ⇒ 累积 **500°+**，首尾直线 **7.5 m → 3.3 m**，
      画面里龙蜷成一个圈（保险丝"身长"当场报警）。
  - ⇒ 要往姿态上叠东西（扑咬 / 蓄势 / 拉起），就把参数**并进同一次绝对写入**
    （`ApplySpineOffsetsRaw(..., extraPitchDeg, extraRootGain, extraHeadGain)`），
    不要另开一次遍历。
  - **★ 攻击全程也要保持 S 形**：旧实现的 Tell/Dive/Strike/Recover 四个相位里
    **一次都没调用** `ApplySpineOffsetsRaw` ⇒ 一进攻击身体就变直。
    抽一个 `ApplySwimWave(scale, extraPitch, …)` 让各相位复用同一条连续相位（`Time.time`）
    即可无缝衔接。
  - **★ 分组统计必须按「真的在攻击中」判定**：`_dive` 在攻击结束后**不会回到 None**，
    会一直停在 `Recover` ⇒ 按相位名分组会把"已经回到盘旋"的 50 多帧也算进攻击段。
  - **★ 方向约定**：链是 **i 小 = 尾/根侧**（`drgon_03`→`drgon_00`），
    而 `ApplySpineOffsetsRaw` 的形参历史上叫 `headGain/tailGain`，**语义与名字相反**，
    写包络时别被名字带偏。

## 七、工程与协作

1. **`Time.timeScale` 单一所有权**：`HitStop` 恢复写回「进入前的值」⇒ 进暂停/结算前先 `ForceEnd()`。
2. **多播事件是单点故障放大器** ⇒ 处理器调外部系统必须自己收敛异常。
3. **★ 临时物统一 `A<数字>_` 前缀**（清理正则 `^A\d+_`）｜**计数要逐帧累加峰值**。
4. **★ git 安全（09-17 事故换来）**：两台机器交替提交 ⇒ **一律 `merge`，不要 `rebase`**
   （rebase 要重写工作区+索引，被中断可能连对象库一起毁）；对象库一眼判据 =
   `git count-objects -v` 的 `in-pack: 0` + `objects/pack/` 为空；**重建前先备份工作区改动**。
5. **★ 跨机搬运必须连目录自身的 `.meta`**，否则 Unity 重新生成 GUID、
   prefab 里所有 `{fileID:…, guid:…}` 引用**当场静默断裂**（不报错，只是模型没了）。
6. **★★★ 「改了 .cs 但运行时读到旧值」要分三层判据，只看 DLL 时间戳一定会被骗**（09-18 实测）：
   - **第一层 · DLL 文件内容**：`grep -ac "<新符号名>" Library/ScriptAssemblies/Assembly-CSharp.dll`。
     **mtime 会撒谎** —— Bee 复用缓存时只更新时间戳，连**字节大小都完全一致**。
     ★ 最灵的判据是**新增一个类**（DLL 里必须出现它的名字）＋**删掉的方法必须消失**。
   - **第二层 · 运行时真正加载的程序集**：DLL 文件对 ≠ 内存里的程序集对。
     本次证据：`_PokeCompile` 已在 DLL 里（命中 2 次），但 Play 里回读字段仍是旧默认值。
   - **第三层 · 回读被测字段**：最终判据只能是"跑一次、把值打出来"。
   - **触发手段按可靠性排序**：**新增一个 `.cs` 文件**（必然重编）＞ `ImportAsset(ForceUpdate)`
     ＞ `Refresh(ForceUpdate)` ＞ `RequestScriptCompilation()` —— 后三者在本机**全都出现过无效**。
   - `EditorUtility.RequestScriptReload()` 能强制域重载（日志出现 `domain reloads=1`），
     但**本机上仍未能把新默认值带进 Play** ⇒ 遇到时**重启 Unity 最省时间**，别硬啃。
   - 域重载会把**当前打开的场景换成默认/空场景** ⇒ 之后再跑探针要先 `OpenScene`；
     而 `OpenScene` 在 Play 模式下会抛 `This cannot be used during play mode`
     ⇒ **`--runtime` 的探针跑完务必 `stop`**（老坑又踩一次）。
7. **★ 临时占位脚本（如强制编译用的空类）用完立刻删**，别让它进提交。
   推荐命名 `_PokeCompile.cs` 这类一眼可辨的名字，并在文件头写清"为什么需要、何时删"。
