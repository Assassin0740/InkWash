> 用途：记录本项目引入了哪些第三方框架/库、版本、装法、授权，以及**如何在全新克隆里复原**。

> 所以框架源码**不在版本库里**。换机器或重新克隆后，必须按本文档复原依赖。

## 二、QFramework

### 为什么用它

项目需要音频管理、事件总线、对象池、UI 栈等通用设施。这些是纯样板代码，
手写没有技术价值也容易出错，因此交给成熟框架。**核心玩法模块（角色控制、
第三人称相机、战斗与刀光）仍为自研** —— 那是论文"设计与实现"的主体，
不能外包，且成品资产的手感与本项目目标不一致，改造起来反比自己写慢。

### 装法

```bash
python Tools/install_qframework.py          # 安装（已装则跳过）
python Tools/install_qframework.py --check   # 只体检，退出码 0=已装 / 1=未装
python Tools/install_qframework.py --force   # 重装
```

脚本做四件事：

1. 下载 `QFramework.Toolkits.unitypackage`（优先复用 `_RawDownloads/QFramework/` 缓存）
2. 解包到 `Assets/ThirdParty/QFramework/`，**保留 GUID**（`.meta` 原样落位，引用不断）
3. 删除包内嵌套的 18 个示例 `.unitypackage`（占 5 MB，Unity 用不到）
4. 修补 `Toolkits/UIKit/Scripts/Resources/UIRoot.prefab`

### 关于第 4 步的修补（上游包自身缺陷）

上游包里的 `UIRoot.prefab` 中，`UICamera` 节点上有两个组件被序列化成了
**没有类型字段的空壳 `Behaviour:` 块**（`!u!92` 与 `!u!124`）。Unity 无法解析，
导入时报：

```
Problem detected while importing the Prefab file: '.../UIRoot.prefab'.
Component at index 3 could not be loaded when loading game object 'UICamera'. Removing it.
```

这两个组件不携带任何数据（Unity 已经把它们丢弃），所以脚本直接把这两个 YAML 块
连同 `m_Component` 里的引用一并摘掉，报错永久消失。
> 若将来重新引入完整包，记得重跑安装脚本，它会自动重新打补丁（幂等）。

### 目录结构（安装后）

```
Assets/ThirdParty/QFramework/
├── Framework/Scripts/            QFramework.cs 本体（程序集 QFramework）
└── Toolkits/
    ├── _CoreKit/                 ActionKit/SingletonKit/PoolKit/EventKit/FSMKit/PackageKit…（QFramework.CoreKit）
    ├── AudioKit/                 音频管理（AudioKit）★ 本项目使用
    ├── ResKit/                   资源管理（ResKit）
    ├── UIKit/                    UI 管理（UIKit）
    └── SupportOldQF/             旧版兼容层
```

规模：约 1017 个文件 / 862 个 `.cs` / 8.8 MB。

### 程序集引用关系

```
QFramework  ←  QFramework.CoreKit  ←  AudioKit
```

三个程序集均 `autoReferenced: true`，因此默认程序集 `Assembly-CSharp`
（即 `Assets/_Project/Scripts/` 下的自有脚本）**可以直接使用**，无需自建 asmdef。

### 注意：PackageKit 的硬编码路径

`_CoreKit/PackageKit/.../PackageData.cs` 里写死了 `Assets/QFramework/Framework/`。
本项目的安装位置是 `Assets/ThirdParty/QFramework/`，因此 QFramework 自带的
**PackageKit 更新窗口不可用**。本项目不使用该窗口，无影响。
其余硬编码路径均指向 `Assets/QFrameworkData/`（框架运行时数据目录，与安装位置无关）。

## 三、PrimeTween

### 装法

`Packages/manifest.json` 中两条改动，**不要手工把源码拷进 `Assets/`**：

```json
{
  "dependencies": {
    "com.kyrylokuzyk.primetween": "1.4.11"
  },
  "scopedRegistries": [
    { "name": "npm", "url": "https://registry.npmjs.org", "scopes": ["com.kyrylokuzyk"] }
  ]
}
```

Unity 解析后落在 `Library/PackageCache/com.kyrylokuzyk.primetween@1.4.11/`（不入库）。

> 注意：GitHub 仓库 `KyryloKuzyk/PrimeTween` **只有文档与 Benchmarks，没有源码**，
> 官方推荐的安装途径是 Asset Store 或上述 npm registry。所以**不能**用
> `git+https://github.com/...?path=PrimeTween` 这种写法（会 404）。

### 授权要求（务必遵守）

PrimeTween 用的是**自定义免费许可**，不是 MIT。核心条款：

- ✅ 允许在免费/商业项目中使用并修改
- ✅ 允许作为依赖用于衍生项目（模板/库/仓库），**但前提是通过 npm 方式安装**
- ❌ **禁止**把 PrimeTween 的源码或 `.tgz` 压缩包放进衍生项目里分发
- ❌ 禁止转售 PrimeTween 本身

因此本项目**只通过 npm 依赖引用**，源码不落进 `Assets/`，不构成再分发。
将来若要把工程打包成模板/库发布，这条约束依然成立。

### 依赖

npm 包版的 `PrimeTween.Runtime.asmdef` 引用了 `Unity.Burst` 与 `UniTask`。
Burst（+ Mathematics）会被**自动拉取**；UniTask 未安装也不影响编译。

## 四、复原步骤（全新克隆）

```bash
# 1. 还原三方素材（Quaternius / Kenney 等）
#    见 Docs/第二批素材下载清单.md

# 2. 还原 QFramework
python Tools/install_qframework.py

# 3. PrimeTween 无需操作，Unity 打开工程时会按 manifest.json 自动解析
```
