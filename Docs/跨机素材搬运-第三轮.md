## 二、源机器上的实测结论

### 2.1 场景真实依赖：13 个 Nature FBX（不是 5 个）

新增 `Tools/scene_deps.py`，直接解析二进制场景的 externals 表：

```
引用 guid 数: 58 （可解析 57，悬空 0）
其中落在被 ignore 目录内、跨机必须搬运的资产: 14 个
   Assets/Char_Feng/Fbx/Feng.fbx                                  ← 已搬
   Assets/ThirdParty/Quaternius/StylizedNatureMegaKit/FBX (Unity)/Bush_Common.fbx
   .../DeadTree_2.fbx   .../DeadTree_4.fbx
   .../Pine_1.fbx  .../Pine_2.fbx  .../Pine_3.fbx  .../Pine_4.fbx  .../Pine_5.fbx
   .../Rock_Medium_1.fbx  .../Rock_Medium_2.fbx  .../Rock_Medium_3.fbx
   .../TwistedTree_1.fbx  .../TwistedTree_3.fbx
```

再把这 58 条逐条还原成「引用方 → 来源资产」：**场景里 21 个 `PrefabInstance` 中，
20 个正是这 20 个道具，来源逐个精确指向上面这批 FBX**（第 21 个是 `Player.prefab`）。
道具命名链也印证：`g_props.cs` 用 `PrefabUtility.InstantiatePrefab(fbx)` 生成、
对象名 = FBX 名 → `g_props3.cs` 原地改名成 `Prop%02d_<方位>_<FBX名>`。

⇒ **13 个 FBX 里没有一个在上一轮那个闭包 zip 里**（`InkWash_ThirdParty_closure_20260917.zip`
的 78 条目中 Nature 相关条目 **0**）。所以那边看到的不应是"部分缺"，
按 13 个（覆盖 20 个道具）一起修。

### 2.2 `check_clone_deps.py` 的"通过"是假阴性（这条最要紧）

那边已经指出：`Main.unity` 是二进制、guid 是裸值，而自检是文本正则 ⇒ 读不到。
**实测确认**，并且工具本身现在会自己说出来：

```
[C] 扫描 guid 引用（Assets + Library/PackageCache）
    ★ 非文本资产 1 个，**文本扫描读不到它们的引用** —— 已跳过：
        Assets\_Project\Scenes\Main.unity
      这不是「没有依赖」，改由下面的 [E] 核验。

[E] 二进制资产的外部引用核验（清单来自源机器）
    清单条目: 57 条（不含内建）
    [OK ] 全部解析得到，二进制资产的引用完整。
```

做法：源机器用 `scene_deps.py --manifest` 导出
`Tools/reports/scene_externals.txt`（`guid → 期望路径 → 引用方`，随 git 走），
目标机自检时逐条核验。**只靠文本扫描的那套判据无法覆盖二进制资产，已在 [D] 结论里计入。**

反向验证（挪走一个 meta 再跑）：

| 判据 | 结果 |
|---|---|
| `[C]` 文本扫描 | 照旧 `[OK]`（**假阴性**） |
| `[E]` 清单核验 | `!! 缺失 Assets/.../Pine_4.fbx`（**抓到**） |

### 2.3 ★ 上一轮闭包漏掉 Nature 包的技术根因

`transfer_closure.py` 里确实是"二进制走字节扫描"，但那一步用错了编码：
`bytes.fromhex(guid)`（文本原序），而 **Unity 二进制里 guid 的每个字节两位十六进制是互换的**：

```
.meta 文本            d3ef99fc 6191a464 0bd69aea bb667991
文件里实际 16 字节     3d fe 99 cf 16 19 4a 46 b0 6d a9 ae bb 66 97 19
                     ↑ 每字节 nibble 互换（d3↔3d, ef↔fe, fc↔cf …）
```

**用错这一步 → 字节扫描恒 0 命中、且不报错** ⇒ 二进制场景的依赖被静默判为"没有"。
这就是 13 个 Nature FBX 一个都没进清单的原因，也解释了那边为什么"拷了 ThirdParty 依然缺"。

> 判据纪律（与项目一贯的教训同源）：**「扫到 0 条」必须当成失败，不能当成「没有依赖」。**
> 现在 `scene_deps.py` 在「文件里有 N>0 个对象却读到 0 条引用」时会直接返回错误码。

## 三、这次要发的东西

`D:\Unity Project\InkWash_Transfer\` 下两个包，**选一个**：

| 包 | 条目 | 体积 | 用途 |
|---|---|---|---|
| **`InkWash_NatureKit_full_20260917.zip`** | 189 | **46.9 MB** | **推荐**：整个 `StylizedNatureMegaKit` 目录（FBX + 贴图 + 全部 `.meta`）。解压到工程根即覆盖成源机器那一套，guid 必然对上 |

两者都带 `KIT_MD5.txt`（源机器全目录 md5 清单）。

选 full 包的理由：贴图 38 MB 里可能不为道具所用（道具材质已被 `g_props.cs` 换成
`mProp` 覆盖），但 `*.fbx.meta` 的 `externalObjects` 里记着贴图 guid ——
只换 `.meta` 而贴图对不上，会留下一批"贴图悬空"警告。full 包一次到位。

**解压位置：工程根**（不是 `Assets/` 下），包里路径就是 `Assets/ThirdParty/Quaternius/...`。
