## 二、到底需要搬什么：闭包 = **78 文件 / 168 MB**

`ThirdParty` 全量 640 MB，但真正被工程引用的只有一小部分。
新增工具（源机器跑）：

```bash
python Tools/transfer_closure.py          # 算闭包 -> Tools/reports/transfer_manifest.txt
python Tools/verify_transfer_closure.py   # 反证：只给这批文件，还剩几处悬空
```

判据：从**入库资产**（非 ignore 的 .prefab/.unity/.mat/.controller/...）出发，
按 `guid:` 引用做 BFS，落到被 ignore 目录的文件。两个细节：
- `Main.unity` 是**旧二进制格式**（133 KB），guid 在里面是 16 字节裸值 ⇒ 工具额外做了字节扫描；
- 被引用 FBX 的 `.meta` 里还有 `externalObjects` 贴图重映射，也要跟着递归。

闭包分解（`ThirdParty` 部分 21 个非 meta 文件）：

| 包 | 文件 | 说明 |
|---|---|---|
| **KayKit** | 11 | `Rogue_Hooded.fbx`、`Rig_Large_CombatMelee/General`、`Rig_Medium_CombatMelee/CombatRanged/General/MovementBasic`、`Skeleton_Golem/Mage/Minion.fbx`、`skeleton_texture_A.png` |
| **Quaternius** | 2 | UAL1 / UAL2 的 `*_Standard.fbx`（动画库） |
| **Ziyuan** | 8 | 5 个 `_fbx`（龙/不死兵/兽人/山怪/LP 龙）+ 3 张贴图 |
| Char_Feng / W_Sword / BGM | 已到位 | 见上一轮 |

其余全是 `.meta` 与**祖先目录的 `.meta`**——这些不能省，Unity 靠它认文件夹、
靠 `.meta` 里的 guid 让 prefab 引用解析得上。

## 三、三条搬运路线（选一条）

### A. 两机接同一网络（零介质，最省事）

把其中一台切到对方所在的 Wi-Fi/热点，确认 `ping` 通之后，**在源机器（本机）**跑：

```bash
python Tools/push_transfer.py --target "\\\\192.168.16.102\\e$\\Programs\\Project\\InkWash"
```

按闭包清单逐文件复制并建目录；先加 `--dry-run` 可预演。
（不用 robocopy 的原因：`/IF` 只吃通配符、**不吃清单文件**，
而精确搬运必须按 guid 闭包逐文件来。）

本机已模拟目标实测通过：**78/78 文件、168.0 MB 全部落地**。

### B. U 盘 / 移动盘（最稳，推荐）

整目录拷，容忍清单失准：

```bash
python Tools/push_transfer.py --target "E:\\" --full
```

复制整个 `Assets/ThirdParty`（≈640 MB），自动跳过两边**字节一致**的龙 fbx（省 13 MB）。

### C. 聊天工具 / 网盘

已打好包：

```
D:\Unity Project\InkWash_ThirdParty_closure_20260917.zip   114 MB / 78 条目
```

包内保留 `Assets/...` 相对路径，**在目标工程根解压**即可。
