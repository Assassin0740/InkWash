# 敌人「实渲 0 像素」诊断记录（MoShan / MoGuai）

> 起始：09-17 发现 `Z_Enemy_MoShan`（14/14 网格齐全）与 `Z_Enemy_MoGuai`（10/10）**实渲 0 像素**，
> 而 `Tools/cs/chk_enemy_vis.cs` 判它们 ✅（它只查 `sharedMesh != null`）。
> 本文记录**已排除项**与**两个新度量坑**。**根因仍未定**，但排除法已经收得很窄。

## 一、现在能确定的事

| 结论 | 证据 |
|---|---|
| **MoShan / MoGuai 确实完全没渲染出来** | 品红哨兵底（抖动 ≤19 < 阈值 24，判据干净）下 **0.00%**，且与取景无关 |
| **不是视锥剔除** | `dg_enemy_cull` 三档对照：A 原样 / B `updateWhenOffscreen=true` / C B+`localBounds` 设超大 ⇒ **三档全 0.00%** |
| **不是取景尺度问题** | `dg_enemy_far` 正交尺寸 5 → 50 → 500 → **5000 m** 跨 1000 倍，读数**恒定不变** |
| **不是材质 null** | 14 个 SMR 的 `sharedMat` 全是 `M_Ink_Enemy_MoShan`，`shader=InkWash/InkCharacter` |
| **不是被禁用 / 不在层级** | 全部 `enabled=True`、`activeInHierarchy=True`、`layer=0`、相机 `cullingMask=-1` |
| **MoGu / MoLong 是正常的** | 品红底 0.49%（MoGu，正交 8 m 固定取景）/ 4.92%（MoLong） |

**共同点**：`m_RootBone: {fileID: 0}` + `m_Bones` 全 0（MoShan 26 / MoGuai 97 / MoGu 80 条全零）。
**但 MoGu 也是全零却渲染得出来** ⇒ **这条不是充分解释**，别把它当根因。

**仍待查**（下一步）：网格本身 —— `mesh.subMeshCount` / `Mesh.GetIndexCount(0)` / `mesh.bounds`
是否与能渲染的 MoGu 有差异。

## 二、★ 两个新度量坑（本轮的最大产出）

### 坑 1：**8-bit RenderTexture 的 dithering 会让哨兵背景色抖动出阈值**

`Camera.Render()` 写 8-bit RT 时 Unity 会做抖动（dithering，Bayer 图案）。实测：

| 哨兵色 | 抖动后的实际像素值 | 与背景差 | 阈值 24 下 |
|---|---|---|---|
| **绿 (0,255,0)** | `(0,240,0)` / `(11,238,11)` / **`(25,240,25)`** / **`(44,240,44)`** / `(62,240,62)` | **最大 62** | **判成"非背景"** ⇒ 恒定假噪声 |
| **品红 (255,0,255)** | `(240,0,240)` / `(236,0,236)` / `(240,0,239)` | **最大 19** | 判成背景 ✅ 干净 |

- **绿底的假噪声实测 = 25.63%（4 档取景完全恒定，且 MoShan/MoGuai 两个不同模型数值相同）**
  —— 这两个"太巧的巧合"就是它是噪声的铁证。
- 出图上表现为**几乎看不见的同心条纹**（就是 Bayer 抖动图案），肉眼极易误判成"模型轮廓"。
- **规矩：哨兵背景色要选"抖动幅度 < 阈值"的色。**
  本品红抖动 ≤19 配阈值 24 是安全的；纯绿抖动到 44 就穿模。

> ⚠ 我一度据此推断"MoShan 渲染成了品红（missing material）"—— **该假设被 `dg_enemy_far` 推翻**。
> 绿底的 27.14%、25.63% 全是噪声，不是模型。

### 坑 2：**阈值不能骑在噪声带上（`luma < 100` 那次）**

想做"深色像素"判据时用 `luma < 100`，结果**四个 prefab 全都报 67.87%，包括什么都没画的 MoShan**。

原因：品红抖动值 `(240,0,240)` 的 luma = `0.30×240 + 0.11×240 = 98.4` **< 100**，
而基准色 `(255,0,255)` 的 luma = `104.55` **> 100** ⇒ **同一个纯色背景被阈值劈成两半**。

**规矩：阈值的两侧都要留出 ≥2 倍噪声幅度的余量，并先量一次"纯背景"的读数当零点。**
`非背景像素` 判据在做之前，应当先对**空场景**拍一张，确认读数是 0.00%。

## 三、附带发现的硬事实

1. **`mesh.vertices` 返回空数组**（`vertexCount` 仍报 116 / 9755 / 28082）
   ⇒ **"读顶点真值"这条手段在本工程不可用**。`bindposes` 却读得到（MoShan 26 / MoGuai 97 / MoLong 273）。
   表现：`min` 保持 `float.MaxValue`、`max` 保持 `float.MinValue`，`size=(-Infinity,…)`。
   ⇒ 探针里要**显式检测 `vertices.Length == 0` 并报告**，否则会得到一堆看似合法的 `±3.4e38`。
2. **`renderer.bounds` = `localBounds` × `lossyScale`**（逐分量对得上）
   ⇒ `updateWhenOffscreen=False` 时它就是**由 localBounds 推的**，不是蒙皮真值。
   且 **`localBounds` 与 `mesh.bounds` 不一致**（MoShan `Object_33`：0.639 vs 0.550）⇒ 被显式设置过。
   **⇒ 取景不能信 `renderer.bounds`**（与既有规矩「量 SkinnedMesh 只看顶点真值」同源，但本工程顶点读不到，只能改用固定尺度取景）。
3. **`bones` 全 null 在三家都是**（MoShan/MoGuai/MoGu 各 26/97/80 全 null，只有 MoLong 是 273 个非 null）。
4. `localBounds` 尺度横跨四个量级，与"能否渲染"**没有**相关性：
   MoShan `0.04~1.33`（不渲染）、MoGu `3.2~98`（渲染）、MoGuai `107~1766`（不渲染）、MoLong `122~2518`（渲染）。

## 四、五个探针的分工（都在 `Tools/cs/`）

| 探针 | 回答什么 |
|---|---|
| `dg_enemy_shots.cs`（v2） | 截图集：7 敌人 + 龙，离群过滤取景 |
| `dg_enemy_diag.cs` | mesh/bindposes/bones/材质/layer + 两套取景对照（★ 它一刀切禁用了 MonoBehaviour，别再这么写） |
| `dg_enemy_probe2.cs` | **双背景色对照** + 顶点真值 vs 蒙皮包围盒 |
| `dg_enemy_far.cs` | 跨 1000 倍的取景尺度扫描（用来证伪"几何跑到别处/别的尺度"） |
| `dg_enemy_cull.cs` | `updateWhenOffscreen` / `localBounds` 三档对照（用来证伪"视锥剔除"） |
| `dg_pixel_hist.cs` | **逐色直方图** —— 判断"非背景像素到底是什么颜色"，是分清噪声与模型的最快手段 |

**★ 方法论**：`dg_pixel_hist` 的直方图是这一轮唯一真正推进的工具。
百分比只能告诉你"多/少"，**直方图才能告诉你"是什么"** —— 噪声与模型的差别一眼可见（量化色数 3 vs 18）。
