## 0. 为什么要有这份文档

本文档的起因是一次实机反馈：

> 「龙为什么变成这样了，而且平时为什么不是飞天上的，然后冲下来撕咬一下然后重新飞回去的，你这个机制还没有做好策划案吧」

**这句话点出了两件事，其中第二件是真正的架构问题：**

1. 龙的**材质**出了问题（见 §5，属于缺陷，不是设计）。
2. 龙的**机制**是「把一条会飞的龙当成地面近战怪来实现的」——
   四招被平权塞进同一个 `Attack` 状态，靠**加权随机**决定出哪招，
   盘旋只占 **13%** 权重、持续 4.5 s 就落地。

   ⇒ 结果是：龙绝大多数时间**贴地爬行**，与"中国龙"的形态语言**完全相反**。
   之前没有策划案，所以没人发现"能跑通"和"是对的"是两件事。

**本文档的作用**：把「墨龙是什么」写死在纸面上，让实现有对照物；
以后任何对 `EnemyDragon` 的改动，都必须回答"这是否仍然符合策划案"。

## 1. 设计定位

### 1.1 一句话

> **一条盘踞在云上的中国龙。它不属于地面 —— 地面只是它俯冲下来咬你的那一刻。**

### 1.2 与其它敌人的对比

| | 墨兵 / 墨卒 / 墨魇 | **墨龙（BOSS）** |
|---|---|---|
| 空间 | **地面**二维 | **空—地**三维 |
| 移动 | 走向玩家 | **在玩家上方绕圈** |
| 威胁来源 | 贴身挥砍 | **从上方落下的势能** |
| 玩家应对 | 走位 + 连招 | **看高度判断它要下来了** |
| 情绪 | 压力 | **压迫感 + 预判的紧张** |

### 1.3 核心体验目标

玩家在战斗中应该能持续读到这样一个循环：

```
   ┌─────────────────────────────────────────────┐
   │  ①  龙在高空盘旋 —— 你抬头，知道它随时会下来   │
   │  ②  它收拢、俯冲 —— 影子和声音先到，你开始跑位  │
   │  ③  一口咬下 / 扫尾 / 吐息 —— 交换一次攻防      │
   │  ④  它拉起、回到高空 —— 你有一小段安全窗口输出  │
   └─────────────────────────────────────────────┘
```

**这个循环本身就是 BOSS 的玩法。** 不是"它有四个招式"，
而是"**在它落地的那几秒里，你做什么**"。

## 2. 状态机设计

### 2.1 顶层状态（与现状的差异是本次设计的核心）

```
                    ┌──────────────┐
                    │   Circling   │ ← ★ 默认状态：高空盘旋（新增）
                    │  （高空盘旋） │    龙 90% 的时间在这里
                    └──────┬───────┘
                           │ 选招（按距离 + 冷却 + 阶段）
        ┌──────────────────┼──────────────────┬─────────────────┐
        ▼                  ▼                  ▼                 ▼
  ┌──────────┐      ┌──────────┐      ┌──────────┐     ┌───────────┐
  │  Diving  │      │  Diving  │      │  Hovering│     │  Breathing│
  │  （俯冲） │      │  （俯冲） │      │ （悬停吐息）│    │ （高空吐息）│
  │  → 撕咬   │      │  → 扫尾   │      │          │     │           │
  └────┬─────┘      └────┬─────┘      └────┬─────┘     └─────┬─────┘
       │                 │                 │                 │
       └─────────────────┴─────────────────┴─────────────────┘
                           │ 收招
                           ▼
                    ┌──────────────┐
                    │   Recover    │ 拉起 / 回位
                    └──────┬───────┘
                           ▼
                     回到 Circling
```

### 2.2 关键不变量（实现必须保证）

| # | 不变量 | 为什么 |
|---|---|---|
| **I1** | **`Circling` 是默认态**。没有攻击意图时，龙必须在高空（`hoverHeight`），不许落地。 | 这是用户抱怨的核心：「平时为什么不是飞天上的」 |
| **I2** | **每条攻击都有「落地段」与「离地段」**。攻击结束必须回到 `hoverHeight`，不存在"打完就站在地上"的状态 | 保证循环闭合 |
| **I3** | **俯冲是位移，不是动画**。`Diving` 期间龙的水平位置必须真的朝玩家的**预判落点**移动 | 否则"冲下来"读不出来 |
| **I4** | **同一时间最多一次俯冲**。冷却期内不许连发 | 给玩家喘息的窗口，否则压迫感变成挫败 |
| **I5** | **高度是可读的**。下潜前必须有 **≥0.35 s 的收拢预兆**（身体收紧、俯角出现） | 玩家需要"看得懂"才能反应 —— 这是可玩性的底线 |

## 3. 招式表

### 3.1 招式总览

| 招式 | 空间 | 触发距离 | 时长 | 作用 | 玩家应对 |
|---|---|---|---|---|---|
| **俯冲撕咬** | 空→地 | 3 ~ 7 m | ≈1.6 s | 单点高伤 + 击退 | 侧向闪避（冲刺） |
| **落地扫尾** | 地 | 3 ~ 7 m | ≈1.4 s | 扇形范围 + 击飞 | **拉开距离**（别贴脸） |
| **悬停吐息** | 空（悬停） | 5.5 ~ 14 m | ≈2.2 s | 远程骚扰 + 逼走位 | 跑动躲避墨弹弧线 |
| **高空盘旋** | 空 | 全程 | 持续 | **观察/选招/重置** | 输出窗口 |

> **设计要点**：只有 **扫尾** 是"在地面上的招"，
> 其余全部发生在空中或从空中发起。这就是"龙不属于地面"的机制表达。

### 3.2 俯冲撕咬（DiveBite）★ 用户明确点名的招

```
t=0.00  收拢预兆（I5）      身体绷紧、俯角 -25°、翅膀/鬃毛后掠      0.35 s
t=0.35  俯冲               沿抛物线扑向玩家「预判落点」            0.45 s
         └ 抛物线：水平匀速，竖直用 ease-in（重力感）
         └ 落点 = 玩家当前位 + 玩家速度 × 0.35（预判，逼玩家变向）
t=0.80  咬击判定           头颈前 3.4 m 锥形；命中 ⇒ 高伤 + 强击退  0.22 s
t=1.02  拉起               头颈上抬，身体后仰离地                   0.58 s
t=1.60  回到 Circling      （回到高空，循环闭合）
```

**关键参数**
| 参数 | 值 | 说明 |
|---|---|---|
| 俯冲起点高度 | `hoverHeight` = 3.6 m | 已有 |
| 俯冲水平距离 | `biteLungeDistance` = 3.4 m | 已有 |
| 预判系数 | 0.35 s | **新增**（当前实现是追当前位置） |
| 咬击半径 | `radius` = 1.2 m | 现有 prefab |
| 命中伤害 | `damage` = 22 | 现有 prefab |

### 3.3 落地扫尾（TailSweep）

从空中**降落到地面**后横扫，再起飞 —— 与「撕咬」共用俯冲段，区别在落地后动作。

```
0.00  收拢 → 0.35  俯冲（同上）
0.80  落地（y→地面） + 前摇         0.30 s
1.10  横扫：24 节脊骨自根向梢传播    0.30 s
       └ 命中：扇形（±110°）半径 5 m，击飞强度 7
1.40  起飞回位                       0.55 s
```

**与撕咬的区分**（玩家要能一眼分辨）：
- 撕咬 = **纵深**（冲你脸来，逼你侧闪）
- 扫尾 = **面积**（落地范围大，逼你远离）

### 3.4 悬停吐息（Breath）

**这个招式的意义是"逼玩家移动"**，不是主要伤害来源。

```
0.00  悬停定位（在玩家上方 5.5~14 m，缓慢横移）  0.62 s
0.62  吐息：3 颗墨弹，扇形 9° 散开              0.34 s
       └ 弹速 16 m/s，单颗伤害 14，命中后溅开
0.96  继续悬停 / 收招                            0.70 s
```

> **注意**：吐息**不下降高度**（与撕咬/扫尾的区别），
> 玩家看到它悬着不动吐弹，就知道"这一轮它不下来，我可以打它"。

### 3.5 高空盘旋（Circling）★ 默认态

| 参数 | 值 |
|---|---|
| 高度 | `hoverHeight` 3.6 m（相对地面） |
| 轨道半径 | `hoverOrbitRadius` 6.5 m |
| 角速度 | `hoverOrbitSpeedDeg` 55 °/s（约 6.5 s 一圈） |
| 本体姿态 | 沿切线方向游动（蛇形脊骨波 `hoverAmplitudeDeg` 11°，`hoverFrequency` 0.55） |
| 选招冷却 | 1.2 ~ 2.0 s 随机（避免机械感） |

**盘旋期间必须做的两件事**：
1. **跟随玩家的水平位置**（轨道中心 = 玩家位），让它始终"在你头顶"——
   这是压迫感的来源。不跟随的话玩家跑远了它就成了背景板。
2. **保持朝向玩家**（头微低，像在盯着你）。

## 4. 阶段与数值曲线

Boss 战分三阶段，**越到后面越"不落地"**（象征它越来越焦躁）：

| 阶段 | HP | 盘旋高度 | 俯冲冷却 | 招式权重（撕咬:扫尾:吐息） | 新增 |
|---|---|---|---|---|---|
| **P1 游龙** | 100% ~ 65% | 3.6 m | 2.4 s | 1.2 : 1.0 : 1.0 | — |
| **P2 怒龙** | 65% ~ 30% | **4.4 m** | **1.8 s** | 1.5 : 1.0 : 1.2 | 俯冲**二连**（第二次不拉满高度） |
| **P3 狂龙** | 30% ~ 0% | **5.2 m** | **1.2 s** | 1.8 : 0.8 : 1.4 | 吐息 **5 颗**、散角 14° |

> **阶段切换必须有演出**：整条龙仰头长啸（脊骨波幅度 ×2.5，持续 1.2 s），
> 高度抬升 + 墨晕扩散 —— 让玩家明确知道"它变强了"。

## 5. 材质 / 表现规范（本次缺陷的修复依据）

> ⚠ 这一节记录的是一次**真实事故**：用户截图里龙是「灰/青/红/白/棕」的分段彩虹色。

### 5.1 根因（已取证，`Tools/reports/d1_dragon_mat.txt`）

龙的美术资产来自 Sketchfab `chinese_dragon`，它**没有 body albedo 贴图**。
glTF 里龙体只有两处颜色来源：

```
material[0] MI_b09_00_drg_hair（龙体）
    pbrMetallicRoughness.baseColorFactor = [0.1007, 0.0, 0.0087]   ← 深红棕，纯色，无贴图
    emissiveTexture = MI_b09_00_drg_hair_emissive.png              ← ★ 彩色贴图在这里
    clearcoatTexture / normalTexture = ...
material[1] MI_b09_00_drg_eye（眼睛）
    baseColorTexture = MI_b09_00_drg_eye_baseColor.png
    emissiveFactor = [1, 0, 0]                                      ← 红眼
```

**原作者把颜色画在了 `emissive` 通道里**（一种常见的非 PBR 做法）。
Blender → FBX 转换后，这张彩色贴图落进了模型的漫反射槽，
而我的 `M_Ink_Boss_Dragon` 又把 `_BaseMap` 指向了 **`MI_b09_00_drg_hair_clearcoat`**
（一张**青色的毛发光罩遮罩图**）。

于是两条错误叠加，在 `InkCharacter.shader` 的墨彩回填处被放大成彩虹：

```hlsl
// InkCharacter.shader:469-471
half gh = dot(albedoHue, half3(0.2126h, 0.7152h, 0.0722h));
half3 chroma = (albedoHue - gh) * _ChromaKeep * 2.2h;   // ★ 2.2 是过饱和回填
color = saturate(color * (1.0h + chroma));
```

`2.2` 的放大系数是为**主角那张近黑的贴图**标定的
（`_ChromaKeep` 主体 0.60，贴图彩度仅 0.135 ⇒ 不放大看不出颜色）。
把它套在**本来就高饱和的彩色贴图**上 ⇒ 直接过曝成彩虹。

### 5.2 材质规范（墨龙的正确配置）

| 属性 | 值 | 理由 |
|---|---|---|
| `_BaseMap` | **清空（null）** | 这条龙没有 body albedo；用了就是错图 |
| `_BaseColor` | `(1,1,1,1)` | 颜色交给墨阶表 |
| `_ChromaKeep` | **0.0 ~ 0.15** | 无 albedo ⇒ 无可回填的色相。留一点点只为了让眼睛有点色 |
| `_BandBias` | **−0.42** | 浓墨剪影（与其它敌人同档，见 §敌我色系分离） |
| `_InkDensity` | **0.25** | 无贴图可采样 ⇒ 压低，避免把 clearcoat 的青色当形体 |
| `_Bands` | 4 | 墨分五色 |
| `_InkDark` / `_Mid` / `_Light` | 赭墨暖褐一组（`(0.08,0.055,0.045)` / `(0.27,0.21,0.175)` / `(0.82,0.765,0.69)`） | **敌人的色系**，不是主角的花青 |
| `_OutlineWidth` | 0.018 | 与主角 0.012 区分，BOSS 更重 |

### 5.3 ★ 一条必须遵守的纪律

> **敌人的墨阶参数不许被主角的参数覆盖。**

**已知的实现缺陷**：`InkStylePanel.ApplyStage()` 末行是
`if (_edit != null) Broadcast();`，而 `_edit` 是 Inspector 里配的
**主角材质**的副本 ⇒ 每次切阶段都会把主角的
`_BandBias / _InkDensity / _InkDark / _InkMid / _InkLight` **盖到所有敌人头上**。

`d1` 实测：龙的 runtime 读到 `_BandBias=0.150 / _InkDensity=0.550 /
_InkDark=(0.045,0.065,0.135)` —— 与 `M_Character_Ink.mat` **逐位相同**，
而 `M_Ink_Boss_Dragon.mat` 自己写的是 `-0.26 / 0.62 / (0.08,0.055,0.045)`。

**修复方向**（二选一，见 §6 待办 T3）：
- (a) `Broadcast()` 只作用于 `_edit` 对应的**那一族**材质（按 swap 分组）
- (b) 面板改成"分组编辑"，主角/敌人各有一份 `_edit`

## 7. 验收标准

设计做完要能被**度量**，否则又会变成"能跑通但不对"。

| 指标 | 判据 | 测量方式 | **实测** |
|---|---|---|---|
| **A1 空中占比** | 一场 30 s 的战斗里，龙 `y > 地面 + 1.5 m` 的帧数 **≥ 60%** | 逐帧采样 `_modelRoot` 世界 y | ✅ **0.824**（d11，45 s） |
| **A2 循环闭合** | 每次 `Diving` 结束后 1 s 内高度回到 `hoverHeight` 的 90% | 逐帧采样 | ✅ 结束 `airborne=True`、`lift` 回到 3.60（d17） |

| **A4 有喘息窗口** | 相邻两次俯冲的间隔 **≥ 1.2 s** | 记时间戳 | ✅ **2.92 s**（改按"俯冲开始"计后，d11） |

### 7.1 掩码取法（**这一段比数字重要**）

A5/A6 都要"只在龙身上统计"。这套掩码踩了三次坑，别重蹈：

1. **不要给目标换 `sharedMaterials` 成 Unlit 品红**。实践中龙的渲染器换了材质，
   截出来的帧里龙**仍是水墨色**（疑似 SRP Batcher / 材质实例未刷新）⇒ 掩码 0 px，
   而统计输出的"彩度 0.0000 / 近灰 100%"**看着像满分**。
2. **正解 = 临时独立图层**：把目标递归挪到 31 层，`Camera.cullingMask = 1<<31`，
   `Camera.Render()` 出来就是"只有它"的一帧（背景是天空盒，不是黑）。
   多张对照帧必须**同 tick 背靠背** `Render()`，一 `yield` 就错开 1~2 px。
3. **分离目标与背景要用"亮度分位"，不是"非黑阈值"**。天空盒是**亮灰**
   （实测中位 0.745），`r+g+b > 60` 这种非黑判据会命中**整屏 94%** ⇒
   色相差被稀释到 6.8°（假失败）。正解：阈值 = 该帧亮度**中位数 − 0.10**，
   深色剪影自然被分离出来（实测命中 4.9%，与"6 m 龙占屏比例"吻合）。
4. **统计函数必须自检并报命中数**。命中不足时直接打 `✗ 度量失效`，
   **不许算通过** —— 否则"0 个像素"会伪装成"彩度完美"。

### 7.2 高度曲线（d17 实测，可作为回归基线）

```
盘旋 3.60 m ──Tell(0.35s, 抬到 3.81)──┐
                                      ↓ Dive(0.45s, ease-in 落下)
                              打击 0.65 m（撕咬 1.05 m）
                                      ↓ Recover(0.58s, SmoothStep 拉起)
                              回到 3.60 m ──→ 下一轮
```

| 关键量 | 修复前 | 修复后 |
|---|---|---|
| 起飞到位耗时 | 1.5 s（贴地假装在空中） | **0.5 s** |
| 打击相位最低高度 | 0.12 m（**趴地**，龙身插进地面） | **0.65 m**（腹下留空） |
| 拉起速度 | 指数逼近，末段拖沓 | 指数逼近 ∩ 恒定 14 m/s 下限 |
