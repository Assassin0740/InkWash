## 2. 敏捷框架设计（PMP 映射）

因为是 7 天极限工期，**不套用标准 Scrum 的 2 周 Sprint**，而是压缩成 **1 天 = 1 个 Sprint，共 7 个 Sprint**。理由：反馈周期越短，越能在当天就发现方向错误。

| PMP 知识领域 | 在本项目中的落地形式 |
|---|---|
| 整合管理 | 本计划书即整合基线；每日站会用一条消息汇报，变更走 MoSCoW |
| 范围管理 | 第 4 节 Product Backlog（含故事点）；**范围冻结**，新增需求一律进"Won't" |
| 进度管理 | 1 天 1 Sprint；每日燃尽（见 Excel `燃尽图` 表） |
| 成本（时间）管理 | 故事点即时间成本；每日目标 16 点，超支次日砍 Should 项 |
| 质量管理 | 第 9 节 DoD：编译零错误、Console 无红字、1080p≥60fps |
| 资源管理 | AI = 主要劳动力；人 = 决策/账号/验收三类不可替代动作 |
| 沟通管理 | 每 Sprint 结束输出「截图 + 状态 + 阻塞」三件套 |
| 风险管理 | 第 8 节风险登记册，R3/R5 为高优先级 |
| 采购管理 | 素材获取走 CC0 优先策略（第 6 节） |
| 干系人管理 | 导师 = 关键干系人；每 2 天准备一次可展示的进度快照 |
| 变更管理 | 需求冻结；确需变更须砍掉等量故事点（等价交换） |

**角色分工（关键：把人的时间花在 AI 做不到的事上）**

| 只有你能做的 | AI 做的 |
|---|---|
| 开/关 Unity 编辑器 | 写全部 C# 脚本与 HLSL Shader |
| 注册并登录 Mixamo / Asset Store（需账号） | 通过 Bridge 建场景、挂组件、连引用 |
| 下载素材并放进工程 | 改材质参数、调光照、布点 |
| 看效果做主观判断（"墨味够不够"） | 进 Play 模式、截图、读 Console 排错 |
| 论文里的表述、创新点定位、导师沟通 | 论文素材整理、图表数据、初稿撰写 |
| 最终验收与录屏确认 | 性能分析、优化、测试用例 |

## 3. 游戏设计范围（Demo 版）

**定名**：`墨刃 · InkWash`　**类型**：3D 第三人称水墨动作 Roguelike（单局制）

**核心玩法循环**（对应大纲 4.1）

```
主菜单 → 进入「墨境」一局 → 
  房间①：清怪 → 三选一技能 → 
  房间②：清怪 → 三选一技能 → 
  房间③：精英怪 → 三选一技能 → 
  BOSS → 通关结算 / 死亡结算 → 回主菜单
```
单局目标时长 **5–8 分钟**。

**角色能力**（对应 4.2）

| 动作 | 说明 |
|---|---|
| 轻攻击三段连击 | 第 3 段带前冲位移，可取消后摇接闪避 |
| 蓄力重击 | 破防、高伤害、长后摇 |
| 闪避翻滚 | 含无敌帧（i-frame），可穿身位 |
| 拔刀斩（技能位） | 居合式突进斩，消耗墨气 |

**敌人 3 种**（对应 4.3）

| 敌人 | 行为 |
|---|---|
| 墨徒（近战） | 追击 → 挥砍 → 硬直 → 循环 |
| 墨偶（远程） | 保持距离 → 投掷墨弹 → 被贴近则后撤 |
| 墨魇（精英） | 范围横扫 + 冲锋，有可弹反窗口 |

**局内成长**（对应 4.4）：以 ScriptableObject 定义技能池，升级时加权随机三选一。候选池示例：攻击力↑ / 攻速↑ / 暴击率↑ / 连段扩展至四段 / 墨刃投影（远程剑气）/ 命中吸血 / 闪避距离↑ / 背水一战（低血量增伤）等 **10–14 条**。

## 7. TCP Bridge 接入方案（已执行）

### 7.1 为什么用方式 A

文档给出的三种安装方式里，**方式 A（改 manifest.json）** 适用前提是"中国版 Unity + `packages.unity.cn` 主源"。本工程两条全部满足（版本号 `c1` 后缀 + `packages-lock.json` 里 url 为 `https://packages.unity.cn`），因此直接加一行即可，**不需要**走"内嵌包整目录拷贝"那条路。

### 7.2 已完成的三件事

| # | 动作 | 结果 |
|---|---|---|
| 1 | `Packages/manifest.json` 加 `"cn.tuanjie.codely.bridge": "1.0.81"`，同时补齐 3 个依赖包 | ✅ |
| 2 | 便携版客户端落地 `Tools/unity_bridge.py` | ✅ |
| 3 | 新增 `Tools/bridge.cmd`：自动探测可用 Python 后调用客户端 | ✅ |

> **为什么需要 `bridge.cmd`**：实测本机**没有装独立 Python**（`py -3` 报"无可用运行时"，`python` 命中的是微软商店占位程序）。`bridge.cmd` 会依次探测 `UNITY_BRIDGE_PYTHON` → `py -3` → PATH 中的真实 `python` → 常见安装路径 → 兜底，让你不必先折腾环境。

### 7.3 文档所述的两个"坑"及本项目状态

| 坑 | 文档描述 | 本项目处理 |
|---|---|---|
| **心跳文件路径变更** | 1.0.80 起改到 `<项目根>/Temp/.com-unity-codely.json`，老脚本仍读根目录 | 便携版 `unity_bridge.py` **同时检查 `Temp/` 与根目录**，已修复 ✅ |
| **Editor.log 路径写死 Windows** | 原脚本硬编码 Windows 路径，多开 Unity 时日志只有一份、易串项目 | 便携版支持 Win/macOS/Linux 并可用 `UNITY_EDITOR_LOG` 覆盖 ✅ |

> 另外注意：桥端口是**动态分配**的，不要硬记（文档里那个 51009 是**另一个项目**的实测值，本项目会是别的数字）。

### 7.4 常用命令速查

```bat
cd /d "D:\Unity Project\InkWash"

Tools\bridge.cmd doctor                  :: 体检：打印选中端口 + 心跳/日志来源
Tools\bridge.cmd port                    :: 只打印端口号
Tools\bridge.cmd refresh                 :: 刷新资源库（等导入+编译结束）
Tools\bridge.cmd read_console 50         :: 读 Console 最近 50 条
Tools\bridge.cmd clear_console           :: 清空 Console
Tools\bridge.cmd scene_info              :: 打印场景层级
Tools\bridge.cmd execute_csharp "return Application.unityVersion;"
Tools\bridge.cmd screenshot Tools\screenshots\a.png
Tools\bridge.cmd play                    :: 进 Play 模式
Tools\bridge.cmd stop                    :: 退出 Play 模式
Tools\bridge.cmd json "{\"type\":\"manage_editor\",\"params\":{\"action\":\"get_state\"}}"
```

### 7.5 必须知道的约束

1. **Unity 必须处于打开状态**，且桥未被手动停止；脚本不会替你启动 Unity
2 . **Play/Pause 模式下的写命令会被 WriteGuard 拒绝**，返回 `Command blocked by write guard` —— 这是设计行为，先 `stop` 再写
3. **协议**：连上后先读一行 banner 丢弃 → `8字节大端长度头 + UTF-8 JSON` 收发 → 单帧上限 64 MiB
4. **多开 Unity 时** Editor.log 只有一份，可能发现到别的项目端口 → 用 `UNITY_BRIDGE_PORT` 钉死
