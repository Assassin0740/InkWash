## 四、实现形态（沿用项目既有手法）

**驱动层与渲染层分开**：

```
EnemyDragon  ──调用静态入口──▶  DragonStormVfx（场景单例）
                                  ├─ 强度状态机（目标条数/烟浓度 + 平滑逼近）
                                  ├─ 电弧渲染器（A 与 B′ 共用）
                                  └─ 黑烟渲染器（B）
```

- **场景单例 + 静态入口**，形状与 `Assets/_Project/Scripts/Effects/InkHitVfx.cs` 一致：
  受击方不需要认识特效实现，只调一个静态方法；全场共用一个池、一份材质。
- **惰性池**：首次真正需要时才建，不在 `Awake` 里建（否则编辑期 `AddComponent` 就往场景塞对象）。
- **不产生 GC**：池满时静默丢弃并计数，不扩容。
- **表现层不得带崩玩法链路**：入口不抛异常、不阻塞；池/材质拿不到时**只警告一次**。
- **入口要自愈**（坑表 二-5）：被禁用的 `MonoBehaviour` 不执行 `Update()` ⇒ 静态入口里
  `if (!enabled) enabled = true;`。

### 需要给 `EnemyDragon` 补的接口

现在只暴露了 `GetHeadPosition()` / `GetTailPosition()`，**取不到沿链的发射点**。需要补：

```csharp
public int SpineCount => _spine.Count;
public Vector3 GetSpinePosition(int i);        // i 小 = 尾/根侧（沿用既有方向约定）
public Vector3 GetSpineDirection(int i);       // 用于电弧沿身体主轴的走向
```

### ★ 落地形态（第二十三轮 · 已实现）

```
EnemyDragon.TickStorm()  ──每帧一次静态入口──▶  DragonStormVfx（场景单例，惰性创建）
   （只报「姿态枚举 + 口部喷气量」）              ├─ 条数/浓度状态机（整数阶梯 + 连续平滑）
                                                  ├─ 电弧池（A 与 B′ 共用一套网格与材质）
                                                  └─ 黑烟 ParticleSystem（沿链轮转发射 + 口部锥）
```

三处与本文原稿不同的决定，都是实测逼出来的：

1. **不是"每个 `Do*` 方法里写一行"，而是 `Update()` 里**一处**驱动。**
   原稿按方法名分散触发，但那要保证 8 行 × 三个维度（`_attack` / `_dive` / `IsRoaring`）
   的每条路径都到达且不重复 —— 漏一处是**静默**漏特效。
   现在集中在 `base.Update()`（状态机）与 `UpdateBodyLift()`（容器高度）**之后**读本帧最终状态：
   既不会漏，也不会因为调用顺序不同算出不同的值。**本文 §三 那张表仍是唯一真相**，
   只是"查表"这件事收敛进了一个 `switch`。
2. **接口而不是直接持有 `EnemyDragon`**：新增
   `InkWash.Effects.IDragonSpineSource`（5 个成员），`EnemyDragon` 实现它。
   依赖方向固定为 **玩法 → 表现**；接口调用不装箱 ⇒ 不影响"0 B/帧"。
3. **所有可调数值都放在 `DragonStormVfx`（运行时创建）上，不往龙的 prefab 里塞。**
   龙那边只加了**一个** `bool stormVfx`（开关）。原因是
   `Tools/check_prefab_overrides.py` 会对每个 public 字段报"prefab 未写"，
   特效调参每加一个旋钮就要动一次 prefab YAML —— 把一个**表现层**的迭代成本
   转嫁到**玩法层的资产**上了。

## 五、材质与颜色规约

**★ 本项目 Linear 色彩空间下，`Material.SetColor` 不做 sRGB→Linear 转换 ⇒ 必须按线性值给**
（这条在朱砂描边上已经踩过一次）。

| 用途 | 线性值 | 对应 sRGB | 说明 |
|---|---|---|---|
| 电弧芯（hot core） | `(0.90, 0.97, 1.0)` | 带青的极浅蓝 | 弧带中线，占**半宽**的 ~32% |
| 电弧辉光（outer） | `(0.30, 0.78, 1.0)` | 饱和青 | **青白**，主视觉 |
| 电弧强度乘子 | `_Intensity` 默认 **1.8** | — | 乘在颜色上（HDR），配合 Bloom 读"白热" |
| 黑烟 | `(0.020, 0.021, 0.025)` | 近墨黑 | 与 `InkHitVfx.inkColor (0.055,0.062,0.082)` 同族、更深 |
| 烟中电弧 | 顶点色 alpha × **0.55** | — | 比主体电弧暗，读作"藏在烟里" |

**层级关系**：青白是冷色、墨黑是无彩 ⇒ 与龙身的**赭墨暖褐**（`_ChromaKeep 0.10`）形成冷暖分离，
不会和朱砂描边 `(0.48,0.035,0.022)` 抢读。**浓淡轴不单独承担区分**（坑表经验）⇒ 靠冷暖 + 亮度。

### ★★ 修正（第二十三轮）：电弧**不能**用加色混合 `Blend One One`

本文原写「特效是加在墨色之上的光」+ HDR 乘子 ⇒ 暗底上成立，但**本项目的背景是宣纸**：

- `InkSky` 地平线 `(0.966, 0.963, 0.952)`、天顶 `(0.862, 0.874, 0.888)` ⇒ 近白；
- 加法在近白底上 **白 + 青白 = 仍然是白** ⇒ 屏幕上看不见；
- 墨龙的脊骨只有 ~0.1 m 粗、电弧抖动幅度 0.05~0.16 m ⇒ 一条电弧**总有一半伸到纸色背景上**，
  那半截会凭空消失，读起来像"电被切断了"。

⇒ 改成 **`Blend SrcAlpha OneMinusSrcAlpha` + 饱和青辉光 + 带青的近白芯**
（`Assets/_Project/Art/Shaders/InkArc.shader`）：在暗墨身子上是亮青、在纸白上是深青，两头都读得出。
"白热"交给 `_Intensity` 与 Bloom，不再靠加法。
