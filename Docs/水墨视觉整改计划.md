# 水墨视觉整改计划

> 承接用户反馈：「这个水墨风还是有点奇怪，而且没有什么纹理的效果，整体的这个视觉效果特别差，
> 我需要你重新写一个计划，然后根据计划去进行」
>
> 立项日期 2026-09-15 ｜ 方向已定：**写意重墨** ｜ 参考图 `Tools/screenshots/style_ref/`

---

## 0. 为什么这次要重写计划，而不是继续调参

前三轮（S6 及之前）我一直在**加东西**：加材质、加提亮、加特效、加纸纹。每一条单独看都"改对了"，
但画面就是不像水墨。原因不是哪一项调错了，是**结构问题**：

> 我一直在「**给几何体上色**」，而水墨画是「**给画面分墨阶**」。

具体地说，我此前的心智模型是：给每个物体一个墨色材质，让它受光后"看起来像墨"。
但水墨画的逻辑是反过来的 —— **画面上的墨是有限的、分层的、由浓到淡排布的**，
物体的颜色是这个分层的结果，不是它的输入。

这个心智模型错了，于是所有参数都在错误的坐标系里找最优值，怎么调都不对。

**本轮把坐标系统换掉**：先定义画面的墨阶阶梯，再让光照结果去**查表**。

## 1. 诊断：六个病，附实测证据

我读了全部 8 个 shader、5 个 Feature 脚本、9 个材质、渲染器资产与光照设置，
并对照最新实机截图 `Tools/screenshots/look/look_1_idle.png`（全屏亮度集中在 0.85~0.95）。
结论：**画面上一共只有纸白，没有墨**。拆成六个可独立修复的病：

### 病 1（最致命）明度层次塌缩成一条线 —— 墨分五色失效

`InkSurface.shader` 的亮度公式：

```hlsl
half ambient = saturate(dot(sh, 0.333));      // 环境光
half lit = saturate(lambert + ambient * 0.55); // ← 问题在这
half ramp = Quantize(lit, _Bands, _BandSoftness);
```

而 S6 那轮"去灰"把环境光推到了 `sky 0.885 / equator 0.815 / ground 0.640`（intensity 1.0）。
代入：一个朝上的面 `ambient ≈ 0.885` ⇒ `lit ≥ 0.487 + lambert`，**轻松越过 1.0 被 saturate 削平**。
`Quantize` 于是把绝大多数像素都落在**最高阶** ⇒ 全屏纸白。

这解释了两个现象：
- **为什么"不够白"和"发灰"会同时出现**：受光面被削平到 1.0（白得没有层次），
  而背光面卡在 0.5 左右的中灰（灰得没有墨感）。**两头都不占**。
- **为什么加纹理没用**（见病 2）。

### 病 2 噪声被一个饱和的量化器吃光 —— "没有纹理"的直接原因

`InkSurface` 里噪声唯一的去处：

```hlsl
half jitter = (brush - 0.5h) * _BrushStrength * 0.5h;   // ±0.125
half lit = saturate(lambert + ambient * 0.55h + jitter);
half ramp = Quantize(lit, ...);                          // Quantize 内部第一句就是 saturate(x)
```

因为 `lit` 已经饱和在 1.0，`jitter` 加进去**再被 saturate 削掉** ——
噪声在整个受光区（也就是画面 80% 的面积）**数学上等于不存在**。
调 `_BrushStrength` 当然没反应。这不是"纹理太弱"，是**纹理被结构性消灭了**。

### 病 3 纸纹是纯乘性的 —— 加纸纹 = 整幅变灰

`InkPaper.shader`：

```hlsl
half factor = lerp(1.0h, fibre, _PaperStrength) * grainFactor;   // fibre、grainFactor 都 ≤ 1
half3 outCol = col * factor;                                      // 只能压暗
```

纸纹**只有向下调制**，没有向上。所以"想看见纸纹"必然意味着"整幅变暗"。
S6 那轮为了治"发灰"把 `paperStrength` 从 0.45 砍到 0.26 —— 治好了灰，
代价是**纸纹彻底看不见**。这是一个**零和的错误设计**，必须在数学上解耦。

### 病 4 轮廓线是 1px 等宽细灰线 —— 读起来像制图描边

`lineThickness 1.0`（1080p 下约 1px）、`dryBrushStrength 0.72`。在实机截图里，
角色的轮廓是一条又细又连续、粗细完全均匀的线。毛笔的线不是这样的：
它有**起笔的顿、行笔的涩、收笔的尖**，以及交汇处的积墨。当前只有"距离淡出"一种变化。

### 病 5 底层贴图色相泄漏 —— 画面上唯一的彩色在抢视线

`InkCharacter` 的着色公式保留了底层 albedo：

```hlsl
half3 paperTint = _PaperColor.rgb * lerp(half3(1,1,1), albedo, saturate(1.0h - _InkDensity));
//                                                                  ^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                                                    _InkDensity = 0.75 ⇒ 有 25% 的原贴图直接漏出来
```

三个敌人都挂 `_InkDensity 0.75` ⇒ **KayKit 原贴图的橙色斗篷 + 蓝灰骨头漏出 25%**。
截图里那两个橙裙子小孩就是它。水墨画的第一硬约束是**单色相**，
而这里是画面上饱和度最高、对比最强的元素 —— 视线全被它们抓走，
前面所有的纸白与墨线全部沦为背景噪声。

### 病 6 没有接地与环境关系 —— 东西都"浮"在纸上

没有任何机制让物体与地面产生关系：没有接地墨渍、没有接触阴影强化、
大气透视只作用于墨线（`_DistanceFade`）而不作用于物体本身。
参考图里那种"近处浓、远处淡、脚下有墨渍"的纵深，当前完全不存在。

## 2. 验收指标：把"视觉效果差"变成数字

这是本计划与前三轮最大的区别 —— **每一轮改动都必须能被量出来**。

写度量探针 `Tools/cs/d_metrics.cs`（命名跟随工程 `d_` = 诊断/demo 约定）：
`Camera.Render` 到 RenderTexture → `ReadPixels`，在**探针内部**算完所有统计量落进报告
（不依赖人工看图），同时存 PNG 供人眼复核。

**尺子本身已交叉验证**：探针算出的 M1/M2/M3/M4 与用 PIL 对同一张 PNG 独立复算的结果
**逐位一致**（0.577 / 0.854 / 0.135 / 0.043）——数字可信，不是自说自话。

### 2.1 基线（2026-09-15 20:30，改前，`Tools/reports/d_metrics.txt`）

| # | 指标 | **基线（实测）** | 目标（写意重墨） | 落差 |
|---|---|---|---|---|
| M1 | 亮度 5% 分位 | **0.577** | ≤ 0.15 | ❌ 差 3.8 倍。**95% 的画面比中灰还亮** |
| M2 | 亮度 95% 分位 | **0.854** | ≥ 0.90 | ❌ 连纸白都不够白 |
| M3 | 明度标准差 | **0.135** | ≥ 0.20 | ❌ 层次只有目标的 2/3 |
| M4 | 平均饱和度 | **0.043** | ≤ 0.035 | ❌ 轻微超标（橙斗篷） |
| M5 | 地面纹理能量（\|拉普拉斯\| 中位） | **9.53e-3** | ≥ 76e-3（8×） | ❌ 面上几乎没有纹理 |
| M6 | 背景 − 角色亮度 | **−0.048** | ≥ 0.30 | ❌ **方向反了**：角色比背景还亮 |
| M7 | 暗像素占背景比 | **0.797 %** | ≥ 2.5 % | ❌ 墨太少 |
| M7b | 暗段中位长度（水平/垂直） | 2 / 2 px | — | 辅助诊断量 |
| M8 | 1080p 帧率 | 待测 | ≥ 55 | — |

亮度阶梯（5/20/50/80/95）＝ **0.577 / 0.745 / 0.810 / 0.830 / 0.854**
——**整个画面挤在 0.58~0.85 这条 0.28 宽的窄带里**。全图 min 0.027、max 0.929，
但 5% 分位就已经到 0.577，说明暗像素（墨线）占比不到 1%。

> 这就是「水墨风有点奇怪、没有纹理、视觉效果差」的**全部机制**：
> **画面没有墨，只有一片被压平的亮灰。** 病理见 §1 病 1 与病 2。

### 2.2 判据

> **M1 与 M2 必须同时达标**——这是本计划最容易走偏的地方，也是上一轮翻车的根源。
> 只压暗不抬纸白 = 回到"发灰"；只抬纸白不压暗 = 回到现在这种"一片白"。
> 写意重墨的解法是：**暗部真的暗下去，同时受光面真的亮起来**，靠对比度而不是靠整体明度。

> **M5 与 M7 的分工**：M5 量"**面**上有没有纹理"（中位数，不受墨线宽度污染），
> M7 量"**线**上有多少墨"。两者必须分开——否则加粗墨线会让 M5 假性暴涨。

## 3. 技术方案

### 3.1 显式墨阶表（InkLadder）—— 本计划的核心

**不再让 `Quantize` 输出一个线性插值值，改成输出阶索引后查表**，并且阶距**非均匀**：

| 阶 | 名 | 目标亮度 | 用途 |
|---|---|---|---|
| 0 | 焦墨 | 0.045 | 角色剪影、轮廓、器物 |
| 1 | 浓墨 | 0.130 | 角色暗部、石头 |
| 2 | 重墨 | 0.300 | 主体 |
| 3 | 淡墨 | 0.600 | 墙、平台 |
| 4 | 清墨 | 0.880 | 地面、天空、留白 |

非均匀的理由：真实的墨阶就是不等距的 —— **淡墨区很挤（墨少变化快），浓墨区很开**。
线性 5 等分得到的"水墨"会像色阶图，不像墨。

**同时把 `lit` 的构成改掉**（这是治本）：

```hlsl
// 旧：环境光占 0.55，把一切推向饱和
// 新：环境光只占 0.28，让法线朝向真正决定墨阶 —— 墨阶是"光写的字"，不是"环境摊的色"
half lit = saturate(lambert * 0.92 + ambient * 0.28);
```

配套的**环境光回调**：`sky 0.885→0.46`、`equator 0.815→0.34`、`ground 0.640→0.20`。

> ⚠ 这一步必须和第 2 节的 M2 一起验：环境光降下来后，要靠**主光**把受光面推到纸白。
> 如果受光面也塌下去了，那就是"发灰"复发 —— 立刻回退环境光，改从主光补。

### 3.2 纹理管线：三层噪声 + 方向性拉伸 + 三路输出

**分层**（各自有明确的职责，不能混）：

| 层 | 频率 | 形态 | 职责 |
|---|---|---|---|
| 纤维层 | 高频（~1/2mm） | 各向异性 | 纸的颗粒，**在纸白区也看得见** |
| 笔触层 | 中频（~5cm） | **方向性拉伸** | 皴法/笔痕，"一笔刷过"的方向感 |
| 积墨层 | 低频（~1m） | 各向同性 | 大块的浓淡不均，破掉平涂感 |

**方向性拉伸**是"像笔触"的关键 —— 各向同性噪声只会被读成"噪点/脏"：

```hlsl
// 沿一个世界空间的固定方向把噪声拉长 4~6 倍，得到有方向的笔痕
float2 p = float2(posWS.x * 0.22, posWS.z);   // ← 各向异性比 ≈ 4.5
```

**三路输出**（这是治"纹理不可见"的关键，病 2 的正解）：

```hlsl
// ① 抖动阶边界（保留原有思路，但要在 saturate 之前、且加大）
lit += (nBrush - 0.5) * _BrushStrength;

// ② 阶内浓度调制 —— 新增。让同一墨阶内部有浓淡，这是"墨有呼吸"的来源
ramp = saturate(ramp + (nFine - 0.5) * _FineAmp + (nMottle - 0.5) * _MottleAmp);

// ③ 直接调制最终颜色 —— 新增。幅度必须肉眼可见（目标 ±0.05~0.10 亮度）
color *= 1.0 + (nBrush - 0.5) * _TextureGain;
```

**②③ 与 ① 的本质区别**：① 只在阶边界附近有效（远离边界的像素抖了也还在同一阶）；
②③ 在**整片区域**都有效。S6 只做了 ①，所以画面 80% 的面积（阶内部）永远不会有纹理。
这就是"没有纹理的效果"的完整解释。

### 3.3 宣纸纸性：纤维 + 渗化湿边 + **纸白补偿**

**（a）把乘性调制改成双向调制**（治本，解 病 3 的零和问题）：

```hlsl
// 旧：factor = lerp(1, fibre, s)          → 均值 < 1 → 整幅变暗
// 新：围绕 1 双向偏移，均值为 1，纸白不塌
half fibreMod = (fibre - 0.5h) * 2.0h;                 // [-1, 1]，均值 0
half3 outCol = col * (1.0h + fibreMod * _PaperStrength);  // 有亮有暗，纸白守恒
```

这样 `paperStrength` 可以从 0.26 提回 **0.5+**，纤维清晰可见，而**整幅不会变灰**。
上一轮"加纸纹 = 变灰"的死结就在这里解开。

**（b）新增生宣渗化湿边**（"像纸"的标志性特征，当前完全没有）：
生宣吃墨后，墨迹边缘会因毛细作用积一圈略深的**水痕**。做法：采样 4 邻域亮度，
在「本像素偏暗 + 邻域存在更亮」的位置加深 —— 即墨块边界外侧的一条深边。

**（c）生宣粗颗粒**：`grainStrength 0.15 → 0.28`（同样改成双向调制）。

**（d）vignette 保持 0.14 不抢戏**（它属于"摄影语言"，不属于水墨语言）。

### 3.4 轮廓线笔意

| 参数/机制 | 当前 | 改为 |
|---|---|---|
| `lineThickness` | 1.0 | **1.7**（期望 M7 从 0.797% 提到 ≥2.5%） |
| `lineStrength` | 1.3 | **1.5** |
| 边缘强度曲线 | 线性 | `pow(edge, 0.7)` —— 提中段，让弱边界"起笔" |
| 交汇积墨 | 无 | `ink = 1-(1-ink)^1.35` —— 多条边界叠合处自然加深 |
| 收笔 | 只有距离淡出 | 叠加一层**低频**飞白，做长距离开断（当前飞白频率太高，读起来是"毛边"不是"断笔"） |

### 3.5 去色：把彩色踢出画面（治 病 5）

`InkCharacter` 里 albedo 先去色，再保留极弱的原色：

```hlsl
half grey = dot(albedo, half3(0.2126h, 0.7152h, 0.0722h));
albedo = lerp(half3(grey, grey, grey), albedo, 0.08h);   // 只留 8% 色相，明暗关系全保留
```

保留明暗的意义：敌人骨头与袍子的**明度差**仍在（形态可辨），但**色相差**被消灭。
去色后 `_InkDensity` 从 0.75 提到 **0.88**（大量用贴图的明暗信息来做墨阶层次）。

### 3.6 分层、接地与大气透视

- **接地墨渍**：物体与地面接触处加深（用世界空间高度做衰减 + 已有的低频积墨层）。
  这是让"东西不浮在纸上"的最省事手段。
- **大气透视**：把 `_DistanceFade` 的逻辑从"只作用于墨线"**复制到物体着色**上 ——
  远处物体整体往清墨/纸白推。这是参考图里纵深的来源。
- **地面环境墨渍**：地面加低频斑块（`_InkMottle` 已有机制，但幅度不够且被饱和吃掉）。

## 5. 风险与回退

| 风险 | 表现 | 处置 |
|---|---|---|
| **降环境光导致"发灰"复发** | M2 掉下 0.90 | 先回退环境光，改从主光强度补 —— **纸白由受光给，不由环境光平摊给**（本计划核心取向） |
| 重墨导致画面"脏" | M5 达标但观感浑浊 | 限制纹理只作用于**中低频**，高频只留极弱纸颗粒；并检查是否在暗部也加了纹理（暗部不该有纹理） |
| 三层噪声性能超标 | M8 <55fps | 纤维层改用顶点插值/半分辨率；或把积墨层烘焙进 `_BaseMap` |
| 去色后角色辨识度下降 | 三个敌人长得一样 | 保留 8% 色相 + 靠**明度差与墨阶**区分；必要时给不同敌人不同 `_Bands` |
| 写意重墨与论文"三层渲染"框架冲突 | 论文表述 | 三层框架（墨线/宣纸/墨晕）不变，本计划是在**每层内部**加强，不推翻框架 |

## 6. 方向确认（已与用户对齐）

- **墨感**：写意重墨（浓墨重笔、强对比、大面积飞白皴擦）
- **笔法**：待从三张参考图中选定 ——
  - `ref_A_feibai.png` 飞白皴擦型（干笔飞白、笔痕清晰、块面粗犷）
  - `ref_B_pomo.png` 泼墨没骨型（大块墨色渗开、水痕墨渍、几乎无线）
  - `ref_C_baipiao.png` 白描水墨型（细劲墨线勾勒、顿挫起收、淡墨渲染）

> 现实约束（必须说清）：参考图是**手绘/生成画作**，实时渲染无法 100% 复现 ——
> 尤其是 B 的墨渍随机外渗与 A 的笔锋分叉。本计划的目标是**抓住可实时实现的那部分**

### 7.4 E 挖出的真正根因：**主体墨阶塌缩成一张黑剪纸**

差分图一出来就发现：**轮廓关掉和打开，画面几乎一样**。追下去是两处同时在压暗：

- 角色 `ramp ≈ lambert*0.8 + ambient*0.4 + _BandBias(−0.38)` ≈ **0.02** ⇒ 落在最底一阶
- 再乘 `lerp(1, albedo, _InkDensity=0.62)`，而黑衫贴图 albedo≈0.05 ⇒ 又一个**均匀 ×0.41**
- 结果本体 L≈0.04，而轮廓墨色 L≈0.041 —— **线条和身体同色，等于没画**

`e_tonality` 的量化证据（角色本体像素直方图）：

|---|---|---|---|---|---|
| T0（改前） | −0.38 | 0.62 | **0.11** | **66.0 / 33.3** / 0.6 / 0.1 / 0.0 | 0.71 |
| T1 | −0.10 | 0.62 | 0.42 | 24.1 / 45.4 / 12.5 / 18.0 / 0.0 | 0.70 |
| **T2（采用）** | **+0.15** | **0.62** | 0.58 | 4.4 / 26.1 / 18.4 / 38.5 / 12.6 | **0.61** |
| T3 | +0.15 | 0.35 | 0.65 | 3.0 / 26.8 / 5.3 / 44.4 / 20.5 | 0.58 |
| T4 | +0.40 | 0.35 | 0.37 | 0.3 / 5.7 / 3.2 / 35.2 / 55.5 | 0.28 ❌ |
| T6 | +0.65 | 0.15 | 0.31 | 0.2 / 0.3 / 0.6 / 11.4 / 87.4 | 0.15 ❌ |

> **改前 99.3% 的像素挤在焦+浓两阶** —— 这就是"黑剪纸"的量化定义。
> 同时 **"越白越好"被证伪**：T4 往上分离度崩到 0.28，主体糊进纸里。

**设计闭合（本轮最重要的结构认识）**：

> 主体留白 + 分离度交给**墨线轮廓**去提供 —— 这正是《大神》的构造。
> 实测证实：本体 p50 从 0.08 抬到 0.48，而 **M6 稳在 0.547 不动**，
> 因为矩形 p10 已由轮廓墨色（0.043）而不是本体提供。

### 7.5 《大神》参照的落地映射

| 《大神》特征 | 本项目的实现 |
|---|---|
| 粗重、有起收顿挫的墨线轮廓 | **反向外扩壳**：`Cull Front` + `Tags{LightMode="SRPDefaultUnlit"}`（URP 里该批先于 `UniversalForward` ⇒ 天然正确，不需改队列、不需加 RendererFeature） |
| 轮廓**不是等宽** | `graze = 1−\|dot(n, view)\|`，再 `pow(graze, 0.7)` 提中段；`_OutlineFacing 0.72` ⇒ 掠过视线的边才是粗笔 |
| 长距离飞白断笔 | **物体空间**低频 Value noise（`_OutlineScale 5` ≈ 0.2 m 一格） |
| 低处积墨 | 复用接地墨渍的 `_ContactInk/_ContactHeight/_GroundY`，**不新增 uniform** |
| 屏幕空间线宽恒定 | `_OutlineWidth × (1 + 距离×_OutlineDistScale)` |

**两个必须说清的实现坑**：

1. **飞白噪声必须用物体空间**。用世界空间 ⇒ 图案随角色移动"流过"轮廓，走起来整条线沸腾。
   物体空间（蒙皮前静置坐标）与体表是**稳定映射**，图案等于画在皮肤上。
2. **新增 uniform 要同步改 4 个 CBUFFER**（3 个既有 pass + 新 pass），
   且 SRP Batcher 要求四块**逐字段同序同类型** —— 不一致**不报错、不崩**，
   只是 SRP Batcher **静默失效**。本项目为此加了 `Tools/tmp/check_cbuffer.py` 做机器比对
   （手写时确实漏了：字段集合相同但顺序不同）。

### 7.8 M8 帧率的第三次度量修正：**探针自己污染了窗口**

## 8.1 「地上那条斜带」= 中央高台 `Environment/Arena`

**定位手法**：不猜。从相机对屏幕网格打射线（`g_probe_scene.cs`），再**逐物体隐藏后同帧重渲**
（`g_shots.cs`，`Camera.Render()` 可同帧连续调用）做排除法。隐藏 `Environment/Arena` 后斜带消失。

**为什么它会读成「一片脏」而不是「一个台子」**（三条叠加）：

1. 它和地面只差 `_BandBias` 0.04 —— 在量化器里被放大成**整阶**跳变（1/4 = 0.25）；
2. 0.3 m 的高差在 25° 俯视下**看不出来**；
3. **它没有轮廓** —— 没有边，人眼只能把它读成「一片略暗的脏」。

**修复**：给场景 shader 补轮廓 Pass（见 §8.5 同一套），台子 `_BandBias` −0.06、`_Bands` 1。

## 8.2 「墙壁很奇怪」= 墨阶量化器把抖动放大成迷彩

**归因对照实验**（`g_hunt.cs`，逐层关掉再量笔痕能量）：

| 关闭项 | 笔痕能量 | 占比 |
|---|---|---|
| 基线 | 177.13e-3 | — |
| 关主光阴影 | 177.13e-3 | 无关 |
| 关纸颗粒 | 168.75e-3 | 5% |
| 关笔触 | 173.67e-3 | 2% |
| 关积墨 | 177.54e-3 | 无关 |
| **关量化 `_Bands=1`** | **28.16e-3** | **84%** |

**根因**：`Quantize` 在「单阶」时被我写成「全亮」，而**大面积平面根本没有形体明暗**，
量化器唯一的输入就是 `_BrushStrength` 抖动出来的噪声 —— 被整阶放大成大块迷彩斑
（0.02 的抖动 → 0.25 的台阶，12 倍）。

**修复**：`Quantize` 在 `steps < 0.5` 时返回 `saturate(x)`（=**真正关闭量化**，而不是全亮），
墙/地/台 `_Bands` 1、墙 `_BrushStrength` 0.55→0.08。
**复测：177.13e-3 → 44.46e-3；明度范围 [0.165, 0.728] → [0.585, 0.776]。**

## 8.3 「不是有素材吗，有地图素材吗」——清点后的实情

**没有。**全库清点：

| 素材包 | 实际内容 |
|---|---|
| Kenney（三包） | **全是音效** |
| KayKit 骷髅系列 | 角色 / 武器 / 骷髅 |
| Quaternius（UAL1/UAL2） | 动画 |
| Quaternius `StylizedNatureMegaKit` | **68 个树石草木**（唯一的场景类素材） |

**用现有素材补**（`g_props.cs` / `g_props2.cs` / `g_props3.cs`）：

- **8 条瓦檐**（`Environment/Eaves/Eave_N/S/E/W` @ y=4.16，`EaveGate_N/S/E/W` @ y=2.94）
  —— 中式院墙的关键特征就是檐口那道水平线，Cube 就能表达
- **20 个自然道具**（松 ×6 / 枯枝 ×2 / 虬树 ×2 / 石 ×6 / 灌木 ×4）布置在**内外墙之间的环带**
  （|x| 或 |z| ∈ 11~20），材质 `M_Ink_Prop`

**踩到的两个坑**（都已写入技能）：

1. 编辑态脚本末尾调 `AssetDatabase.Refresh()` 会**重导 fbx ⇒ prefab 重载 ⇒ 实例的材质 override 丢失**。

2. 按**名字**匹配重排道具 ⇒ 两棵 `Pine_1` 叠在同一个位置（同名）。解法：**按索引**重排 + 重命名唯一名。

## 8.4 「颜色能不能丰富一点」= 墨彩（丹青）注入

**中国画的黑白之外还有丹青**：赭石、花青、藤黄。做法：

```hlsl
// 先把贴图**去色**，只留明暗（衣纹、骨节的形体信息）
half3 albedoHue = albedo;                       // 色相另存
half grey = dot(albedo, half3(0.2126h, 0.7152h, 0.0722h));
albedo = lerp(half3(grey, grey, grey), albedo, 0.10h);
...
color *= lerp(half3(1,1,1), albedo, _InkDensity);

// 墨彩：贴图的「纯色相项」(albedo − luma) 是**零均值**的 ——
// 乘回墨色只改色相、几乎不改明暗。于是形体（墨阶）与颜色（衣料本色）彻底解耦。
{
    half gh = dot(albedoHue, half3(0.2126h, 0.7152h, 0.0722h));
    half3 chroma = (albedoHue - gh) * _ChromaKeep * 2.2h;   // 2.2 = 过饱和回填
    color = saturate(color * (1.0h + chroma));
}
```

**两个必须知道的前提**：

- 本作贴图 `Material_Pbr_Diffuse 2048²` 实测彩度只有 **0.135** —— 不放大 2.2 倍根本看不出来
- 主角贴图**本身色彩很丰富**（花青蓝衣、赭石腰带、皮肤色），所以「去色再回填」能真的回填出颜色

同时把墨色谱加了**冷暖**：焦/浓偏花青、清墨偏宣纸暖黄。

**M4 为什么证明不了这件事**：M4 是全屏彩度均值，画面 80% 是宣纸、角色只占 ~2% 像素 ⇒
角色从纯墨变成蓝衣，M4 只动 0.001。**「肉眼明明有颜色」和「M4=0.028」可以同时成立**。
新增 **M9 角色墨彩**（统计域收进本体掩码）+ 同帧 A/B（`_ChromaKeep` 置 0 再量）。

## 8.5 ★ 人物外轮廓：「世界米」与「屏幕像素」是两回事

**这是本轮最重要的发现，也是用户「外轮廓减淡一点」的真正答案。**

上一轮把 `_OutlineWidth` 从 0.055 降到 0.038，看着像「减淡了 31%」，但：

| 量 | 值 |
|---|---|
| 角色屏高 | 577 px（1920×1080） |
| 屏幕比例尺 | ≈ **266 px/m** |
| `_OutlineDistScale` 0.06 在 6 m 处 | ×1.36 |
| **0.038 m 实际画出来** | **0.038 × 266 × 1.36 ≈ 13.7 px** |

**13.7 px 的线** —— 那是马克笔粗黑边、是「贴纸」观感的来源，离计划里写的 1.8~2.6 px 差 5 倍。

**标定实验**（`Tools/cs/h_oline.cs`，输出 `Tools/reports/h_oline.txt`）：

| `_OutlineWidth`(m) | 实测线宽 | | `_OutlineWidth`(m) | 实测线宽 |
|---|---|---|---|---|
| 0.038 | 13 px | | 0.018 | 7 px |
| 0.030 | 11 px | | 0.012 | **5 px** |
| 0.024 | 9 px | | 0.008 | 4 px |

线性关系 **`px ≈ 300 × 宽度 + 1.6`**，其中 **1.6~2 px 是剪影自身暗缘的「地板」**
（把 `_OutlineWidth` 置 0 也还剩 2 px，去不掉；这也是为什么 M7 的判据不能定到 2 px 以下）。

**落地**（全部显式写进 `.mat`）：

| 对象 | 旧 | 新 | 实测 |
|---|---|---|---|
| 主角 | 0.038 | **0.012** | 13 → **5 px** |
| 剑 | 0.026 | **0.009** | 保锋刃不糊 |
| 敌人 ×3 | 0.032 | **0.014** | 缩小到与主角同量级 |
| 中央高台 | 0.045 | **0.026** | |

场景白盒（墙 0.032 / 柱 0.032 / 地面 0.02）**未动** —— 它们在 10 m 处约 4 px，
本来就合适；主角粗是因为它离相机近（266 px/m vs 墙的 132 px/m）。

> **教训**：线的「粗细」是**屏幕**属性，不是世界属性。凡是 shader 里用世界单位定义的
> 视觉量（线宽、颗粒尺度、飞白尺度），都必须有一条「世界 → 像素」的标定，
> 否则改参数就是在猜。

## 8.6 两把尺子的口径修订（都是「尺子跟着读数走」的前科）

### M6 分离度

**旧口径**：`背景 = 角色包围盒外扩 1.6 倍的环带均值`。两个缺陷：

1. `SkinnedMeshRenderer.bounds` 的投影比实际轮廓**宽 3 倍**（矩形 0.369 视口 vs 实际 0.11）；
2. 那个「环带」其实悬在离角色几百像素处，量的是**远处的墙**。

后果：场景加进深色树石后，全屏背景均值自然下降，**M6 从 0.56 掉到 0.51 —— 是尺子在动，不是画面在变**。

**新口径 v2**（用**品红掩码**取本体，与 `e_tonality` 同一套）：

- 主体墨 = **本体像素**亮度的 10% 分位
- 紧邻背景 = 本体包围盒内、**非本体**像素亮度的**中位**
  （取中位而不是均值：盒内的非本体像素含角色**自己的投影**，少数派但很深，会把均值拽下去：
  实测包围盒内背景均值 0.573 / 中位 0.729）

**目标回到计划原始的 ≥0.30**（本文档 §4 的判据表里写的就是 ≥0.30）。
旧报告里的 ≥0.55 是**旧口径下 0.547 反推出来的** ——
而且它和本作已定的「**主体留白 + 分离度交给墨线轮廓**」的设计直接矛盾：留白主体本来就不该有高分离度。

### M7 墨线宽

**旧口径**：全屏所有非排除区的暗游程中位。三个问题：

1. 语义漂移：加了场景轮廓 Pass 之后，高台/柱/墙脚/石门的线全混进来（水平段中位跳到 6 px），
   量的是「随便谁的墨线」，跟「人物外轮廓」无关；
2. 量程不够：13.7 px 的真值撞上 `MAXSCAN=14`，报告里看着「正常」；
3. **目标本身是假的**：1.8~2.6 px 是**加轮廓 Pass 之前**的基线，当时 M7 量的是别的暗游程。
   拿它当判据，会把一条 13.7 px 的粗黑边判成**合格**。

**新口径 v2**：墨线是 `Cull Front` 的外扩壳，**只可能出现在剪影外侧** ⇒
从每行/每列的剪影端点**向外**扫暗游程（天然排除场景物体），撞上限的一律丢弃。
判据 **3.5~6 px（净贡献 2~4 px）**，并强制报**同帧 A/B**（`_OutlineWidth=0` 重量一遍）。

实测 A/B：**13 → 2 px** ⇒ 证明量到的确实是墨线本身，不是角色身上的暗部（腰带、剑鞘、褶皱）。

### 新增 M9（墨彩）与 M4b 的配合

- **M9 角色墨彩** = 本体掩码内像素的彩度均值 / 90% 分位 / 非灰占比；判据 **净贡献 ≥0.03**（≈通道差 8/255）
- **M4b 高彩度像素占比 ≤0.5%** 继续守着「破调色」不被墨彩带进来（实测 0.13~0.14%）

## 8.10 ★★ 顺带查出：8 项「假失败」—— 验收复位点落在石门外面

收尾跑全回归时，S1 报 **28/3**、S2 报 **49/5**。`git show aae8445:Tools/reports/S1_latest.txt`
证明**这些失败在上一提交就已存在**（数字一致：疾跑 0.000 m/s、受阻 62.236% vs 61.513%），
**不是本轮引入的回归** —— 本轮只动了材质与 shader，`Assets/_Project/Scripts/` 一行没改。

**但它们是假失败。** 症状：

| 报告 | 项 | 读数 |
|---|---|---|
| S1 | 疾跑速度接近设定 4 | **实测 0.000** |
| S1 | 疾跑确实快于步行 | 0.000 vs 1.250 |
| S1 | [C 疾跑(前)] 受阻帧占比 < 2% | **61.513%** |
| S2 | [C 疾跑] 反推片段速度 4.12 | 0.000 m/s（样本 0） |
| S2 | 疾跑步频明显快于步行 | 2.001 vs 2.060 步/秒 |
| S2 | [E 连击] 第 1/2/3 段位移 | 0.000 / 0.000 / 0.749 m（设定 1.2 / 1.5 / 2.6） |

**根因**：`PlaytestHarness.StageAnchor = (0, 0.05, **-14**)`。
这个值定下来的时候，场地里**还没有石门**。S3 加了 `Gates/Gate_N/S/E/W`
（石门在 z = ±10，是**实心碰撞体**）之后，复位点就落到了**南门外**：
向北一跑，3.4 m 处顶住石门 ⇒ 速度读数变 0、受阻帧 62%，连击位移也被墙吃掉。

**实测证据**（`Tools/cs/h_scene_bounds.cs` → `Tools/reports/h_scene_bounds.txt`）：

```
起点 z=-14 → 终点 z=-10.575　位移 3.425 m　平均 1.386 m/s　受阻 62 %
起点 z=-9  → 终点 z=+0.731　位移 9.736 m　平均 3.873 m/s　受阻  0 %
```

**修正**：`StageAnchor` 改为 **(0, 0.05, −8)**（南门内侧 2 m，向北 ≈18 m 跑道；
runSpeed 4.0 × 2.5 s = 10 m）。**一行改动，8 项全部转绿**：

- **S1 31 通过 / 0 未通过 ⇒ M1 达成**
- **S2 54 通过 / 0 未通过 + 姿态 4/0 ⇒ M2 达成**

> **本轮第三条「先怀疑度量本身」**。前两条是 M6 的尺子、M7 的尺子，这一条是**验收场地**。
> 教训：**验收脚本测的是「游戏 + 场地」的合成结果**，场地变了（加了石门）而复位点没跟着变，
> 报出来的是「游戏坏了」。凡是"速度/位移读数为 0"的失败，**先量「起点到障碍物有多远」**。

**顺带一条探针盲区**：`h_scene_bounds` 第一版只扫 `Environment` 层级，**看不到 `Gates/`**，
差点把遮挡物判成"墙"（墙在 ±22，离得远）。定位遮挡时要把**场景里所有带 Collider 的物体**都列出来，
不能只信一层父子关系。
